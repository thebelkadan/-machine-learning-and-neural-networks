## Часть A. Генерация признаков (feature engineering)

Качество классической модели определяется прежде всего **признаками**. Генерация — создание новых признаков из
сырых данных, знаний о предметной области и других источников. Не путать с **извлечением признаков** (feature
extraction — например, PCA, эмбеддинги) и **отбором** (часть B).

| Источник | Примеры признаков |
|---|---|
| **Дата и время** | час, день недели, `is_weekend`, праздник, месяц, сезон; циклическое кодирование $\sin/\cos$ ([зачем](deep.md#11-циклическое-кодирование)); время с последнего события |
| **Агрегаты по сущности** | для клиента: число/сумма/среднее/максимум покупок за 7/30/90 дней, доля отмен, дни с последней покупки |
| **Лаги и окна** (временные ряды) | значение $k$ дней назад, скользящее среднее/стд, разности, тренд |
| **Отношения и взаимодействия** | цена за м², доля кредита в доходе, произведения признаков, полиномы (для линейных моделей) |
| **Категории** | one-hot, frequency/count encoding, **target encoding** (только out-of-fold, со сглаживанием — [формула](deep.md#10-target-encoding-со-сглаживанием)), комбинации категорий |
| **Внешние данные** | погода, курс валют, календарь, геоданные (расстояние до метро/центра), данные о похожих объектах |
| **Текст** | длина, число слов, мешок слов, tf-idf, эмбеддинги (темы [21](../21_word_embeddings_tokenization/README.md), [23](../23_transformer_bert/README.md)) |
| **Модели как признаки** | ответы других моделей (стекинг), номер листа дерева, кластер, расстояние до центроида, ошибка автоэнкодера |
| **Преобразования** | логарифм / Бокс–Кокс скошенных величин, бинаризация, квантили |

Пример из лекции 1: из даты — день недели, час, `is_weekend`. Пример из ДЗ (вероятность отмены заказа такси):
признаки времени, погоды (температура в разные часы, перепады), города, похожих заказов.

**Главное правило генерации — без утечек:** признак должен быть доступен в момент предсказания (агрегаты — только по
прошлому, target encoding — out-of-fold).

**Feature store** (из семинара) — централизованное хранилище признаков: единые определения и расчёт признаков
для обучения и для продакшена (один код → нет расхождения train/serving), версионирование, переиспользование
между командами, контроль точки во времени (point-in-time correctness: значения признаков «на дату события»).

## Часть B. Отбор признаков (feature selection)

**Отбор признаков** — поиск оптимального подмножества признаков по некоторому критерию; удаление избыточных и
нерелевантных признаков.

### B.1. Зачем

| Причина | Пояснение |
|---|---|
| Интерпретация | от чего и как зависит ответ |
| Скорость | время работы алгоритмов часто $O(n)$ по числу признаков; важно для real-time моделей с высоким RPS |
| Борьба с переобучением | особенно для линейных методов (линейная зависимость признаков) |
| Повышение качества | если много шума |
| Удешевление решения | если получение признаков стоит денег/времени |
| Моделирование | хотим, чтобы решение зависело от определённых признаков |

Не путать с **извлечением признаков** (создание новых) и **снижением размерности** (переход в новое признаковое
пространство, тема [11](../11_clustering_dim_reduction/README.md)).

**Типичные ошибки:** надеяться на селекцию (идеальной процедуры нет!); пытаться автоматизировать отбор в отрыве
от основной задачи; выбрасывать информацию, не учитывая особенности данных; отбирать без генерации (их надо
совмещать); забывать, что **отбор — тоже подгонка под выборку**.

### B.2. Три группы методов

| | **Фильтры** (filter) | **Обёртки** (wrapper) | **Встроенные** (embedded) |
|---|---|---|---|
| Как | по отдельному признаку (и таргету) считают оценку качества — статистику | обучают модель на разных подмножествах признаков и сравнивают качество | отбор — часть обучения модели |
| Привязка к модели | нет | да | да |
| Скорость | очень быстро, линейно по числу признаков | медленно (много обучений) | одно обучение |
| Минусы | оценивают признаки по одному («одномерные методы»), не видят взаимодействий | дорого, риск переобучения на отборе | зависит от модели |
| Примеры | дисперсия, χ², MI, ANOVA, корреляции | Add / Del, RFE, Optuna по маске | L1 (Lasso), важности деревьев |

### B.3. Фильтры

**Какую статистику использовать:**

| Признак \ Таргет | Категориальный | Вещественный |
|---|---|---|
| **Категориальный / дискретный** | χ², MI | ANOVA, Кендалл (для порядковых) |
| **Вещественный** | ANOVA, Кендалл (для порядковых) | Пирсон, Спирмен |

- **Энтропия / взаимная информация (MI)** — насколько чётче определён $Y$, если знаем $X$; симметрична, 0 у независимых;
  предпочитает признаки с большим числом значений ([свойства](deep.md#1-энтропия-и-взаимная-информация)).
- **χ²** — отклонение наблюдаемой таблицы сопряжённости от ожидаемой при независимости ([пример расчёта](deep.md#2-хи-квадрат-для-таблицы-сопряжённости)).
- **Дисперсия** — почти константный признак бесполезен: `VarianceThreshold`.
- **t-критерий** (2 класса) / **ANOVA F-test** (K классов) — различаются ли средние признака по классам.
- **Корреляции:** Пирсон (линейная), Спирмен (монотонная), Кендалл (по парам). Корреляция с таргетом — хорошо;
  сильная корреляция с другим признаком — один из пары можно удалить.
- Другие меры: **AUC-ROC признака**; простой алгоритм на одном признаке (это уже похоже на обёртку) — например,
  неглубокий лес на одном признаке ловит нелинейные закономерности.

```python
from sklearn.feature_selection import (SelectKBest, GenericUnivariateSelect, VarianceThreshold,
                                       chi2, f_classif, mutual_info_classif, f_regression, r_regression)
X_new = SelectKBest(chi2, k=20).fit_transform(X, y)                # chi2 — для неотрицательных признаков
GenericUnivariateSelect(f_classif, mode="k_best", param=20)        # mode: 'percentile', 'fpr', 'fdr', 'fwe'
VarianceThreshold(threshold=0.8 * (1 - 0.8))                       # бинарные: одно значение в >80% объектов
f_stat, p_values = f_classif(X, y)                                 # ANOVA: больше F / меньше p — полезнее признак
```

### B.4. Обёртки

Умный перебор признаковых подпространств: выбираем модель и способ оценки (например, 5-fold CV + MSE), запускаем
модель на разных подмножествах, выбираем подмножество с максимальным качеством.

| Стратегия | Суть |
|---|---|
| **Исключение по одному** / перестановка | качество без каждого признака |
| **Backward stepwise (Del)** | начать со всех, каждый раз делать самое выгодное исключение |
| **Forward stepwise (Add)** | начать с пустой модели, каждый раз самое выгодное добавление |
| **Add-Del** | комбинация; совет из практики — $k$ раз [добавить $t$ случайных] + $r$ раз [удалить $s$ случайных] |
| **Subset selection** | перебрать все подмножества мощности $\le k$ |
| **RFE / RFECV** | рекурсивно удалять признаки с наименьшими весами/важностями (+ CV для выбора числа) |
| **Optuna по бинарной маске** | маска признаков — «гиперпараметр»; TPE ищет хорошее подмножество (ДЗ) |

```python
from sklearn.feature_selection import SequentialFeatureSelector, RFECV
from sklearn.neighbors import KNeighborsClassifier
from sklearn.linear_model import Lasso

sfs = SequentialFeatureSelector(KNeighborsClassifier(3), n_features_to_select=3,
                                direction="forward", cv=5).fit(X, y)       # 'backward' — Del
sfs.get_support()
rfecv = RFECV(Lasso(), step=2, cv=3).fit(X_train, y_train)               # для моделей с coef_ / feature_importances_
rfecv.support_, rfecv.ranking_

import optuna
def objective(trial):
    mask = [trial.suggest_categorical(f"f_{i}", [0, 1]) for i in range(X.shape[1])]
    cols = [c for c, m in zip(X.columns, mask) if m]
    if not cols:
        return 0.0
    return cross_val_score(LGBMClassifier(n_estimators=100, verbosity=-1), X[cols], y,
                           cv=TimeSeriesSplit(3), scoring="roc_auc").mean()
```

### B.5. Встроенные методы

- **Коэффициенты линейных моделей:** Ridge (величина весов), **LASSO** (зануляет веса — автоматический отбор).
  Обязательна **нормализация признаков**, иначе величина веса отражает масштаб признака.
- **Деревья и ансамбли:** автоматически выбирают признаки; важность — суммарное уменьшение неоднородности (MDI) или
  ухудшение на OOB при перемешивании признака (MDA) — тема [08](../08_bagging_random_forest/README.md#важность-признаков).
- `SelectFromModel` — отбор по порогу важности/веса.
- **Случайный (теневой) признак:** добавить признак из шума; оставить признаки, важность которых **выше**, чем у
  шума ([обоснование, Boruta](deep.md#9-случайный-теневой-признак)). В ДЗ — наиболее сбалансированный метод (17 признаков почти без потери качества).
- **Перестановка признака:** если после перемешивания значений признака его важность/качество модели почти не
  меняются (или важность растёт) — признак можно исключать.

```python
from sklearn.feature_selection import SelectFromModel
from sklearn.ensemble import ExtraTreesClassifier
clf = ExtraTreesClassifier(n_estimators=50).fit(X, y)
X_new = SelectFromModel(clf, prefit=True, threshold="median").transform(X)

# Теневой признак
X_tmp = X.assign(random=np.random.default_rng(123).normal(size=len(X)))
imp = pd.Series(LGBMClassifier(verbosity=-1).fit(X_tmp, y).feature_importances_, index=X_tmp.columns)
selected = imp[imp > imp["random"]].index.tolist()
```

### B.6. На что смотрят при отборе

1. **Качество решения задачи** (CV).
2. **Штраф за сложность:** $C_p$, AIC, BIC — для моделей, максимизирующих правдоподобие ([формулы](deep.md#5-штраф-за-сложность-aic-bic-c_p)).
3. **Стабильность признакового пространства** — **adversarial validation**: учим классификатор отличать обучение от
   контроля; AUC ≈ 0.5 — выборки похожи; важности признаков этого классификатора — оценки их **нестабильности**;
   отбор = поиск стабильного подпространства ([теория](deep.md#6-adversarial-validation-и-плотностное-отношение)).
4. **Зависимости признаков** — учим модель **выводить признак из остальных**: высокое качество → признак избыточен;
   можно последовательно удалять лишние или проверять, что добавляет новый признак к базовым.

### B.7. Отбор как глобальная оптимизация

Максимизируем $f: \lbrace 0, 1\rbrace^n \to \mathbb{R}$ (маска → качество). **Заведомо нет лучшего алгоритма.** Три группы:

| Группа | Методы | Плюсы | Минусы |
|---|---|---|---|
| **Полный / квазиполный перебор** | все тройки признаков → удалить не попавшие в хорошие подпространства; сначала потенциально лучшие точки | высокая точность | экспоненциальное время, может не завершиться |
| **Направленный поиск** | жадный (до локального максимума), перезапуски, **симуляция отжига**, **beam search** (храним $k$ лучших), локальный поиск | приемлемая точность, просто, быстро | не полный перебор |
| **Стохастическая оптимизация** | **генетический алгоритм** (селекция, скрещивание, мутации), **роевой** алгоритм | просто, нет проблемы локальных минимумов | важен подбор гиперпараметров |

**Дилемма исследования–использования** (exploration vs exploitation): смотреть больше новых точек vs максимально
использовать уже найденное. Регулируется радиусом окрестности, вероятностью мутации и т.п.

### B.8. Дрейф, стабильность, сколько признаков

- **Concept drift** — меняется распределение признаков, таргета или их совместное. Причины плохих прогнозов:
  переобучение, недообучение, дрейф. Инструменты: [Evidently](https://docs.evidentlyai.com/).
- **Pseudo labeling для оценки дрейфа** (семинар): метка = «из какой выборки объект» (разные периоды); если
  классификатор хорошо различает выборки (ROC-AUC ≫ 0.5) — дрейф есть, важности указывают, в каких признаках.
- **PSI** (Population Stability Index): $\text{PSI} = \sum_i(A_i - E_i)\ln\frac{A_i}{E_i}$ по бинам; < 0.1 — стабильно,
  0.1–0.25 — присмотреться, ≥ 0.25 — признак «стал другим». Признак с высоким PSI между train и test часто удаляют,
  даже если он важен ([связь с KL](deep.md#7-psi)).
- **Правило 20 EPV** (events per variable, F. Harrell): на каждый признак — не меньше 20 объектов **минорного** класса.
  10 000 объектов, из них 1000 положительных → не больше $1000/20 = 50$ признаков.

### B.9. Отбор — тоже подгонка

Отбор, сделанный на всей выборке до кросс-валидации, даёт завышенные оценки
([пример](../05_validation/deep.md#4-почему-нужен-отдельный-тест-смещение-отбора)). Отбор — внутрь пайплайна:

```python
from sklearn.pipeline import Pipeline
from sklearn.svm import LinearSVC
clf = Pipeline([
    ("feature_selection", SelectFromModel(LinearSVC(penalty="l1", dual=False))),
    ("classification", RandomForestClassifier()),
])
clf.fit(X, y)
```

## Пример из семинара: 99 признаков, из них 10 информативных

`make_regression(n_samples=200, n_features=99, n_informative=10, noise=20)`, половина — тест:
- линейная регрессия **на всех** признаках сильно переобучается (на трейне $R^2$ близок к 1, на тесте — заметно хуже);
- добавление признаков по убыванию |корреляции| с таргетом находит не все информативные и тянет посторонние;
- `SelectKBest` тоже не избавляет от выбора $k$;
- **Lasso** (`alpha=3`) даёт хорошее решение; **Lasso + RFECV** (`step=2, cv=3`) отобрал **ровно 10** информативных
  признаков (но при другом `step` — уже с посторонними: «нам немного повезло»).

Выводы семинара: без отбора — переобучение; фильтры работают до обучения, но не решают, сколько признаков брать;
встроенные методы используют веса модели; задача отбора вычислительно трудна, простые эвристики не всегда работают.

### Как выбрать метод (итог ДЗ)

| Цель | Метод | Плюсы | Минусы |
|---|---|---|---|
| Максимальное качество | прямой (ручной) отбор всех потенциально полезных | наивысшее качество | много признаков, медленно |
| Баланс качества и эффективности | обёртки (Optuna по маске) | хорошее соотношение | вычислительно затратно |
| Простота и интерпретируемость | встроенные (`feature_importance`, Lasso, случайный признак) | быстро | зависит от алгоритма |
| Скорость (предварительный анализ) | фильтры | очень быстро, не зависят от модели | могут пропустить важные связи |
