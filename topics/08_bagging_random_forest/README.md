# 08. Ансамбли: бэггинг, случайный лес, стекинг

[Шпаргалка (ноутбук)](../../cheatsheet.ipynb) · [Оглавление курса](../../README.md)

**Суть.** Объединяем много моделей, которые **ошибаются по-разному**. **Параллельные** ансамбли
(бэггинг, случайный лес) усредняют сложные модели с высокой дисперсией → дисперсия падает.
**Случайный лес** = бэггинг деревьев + случайное подмножество признаков на каждом сплите (декорреляция).
**Стекинг** обучает мета-модель на out-of-fold прогнозах разных моделей.

| Термин | Определение |
|---|---|
| Hard / soft voting | голосование метками / усреднение вероятностей |
| Bagging | модели на бутстрэп-выборках, ответы усредняются |
| OOB | ≈36.8% объектов, не попавших в бутстрэп дерева; бесплатная валидация |
| Pasting / Random Subspaces / Patches | подвыборка без возвращения / случайные признаки / и то и другое |
| `max_features` | главный гиперпараметр RF: меньше → разнообразнее, но слабее деревья |
| Extra Trees | без бутстрэпа, случайные пороги — ещё разнообразнее и быстрее |
| MDI / MDA / SHAP | важность по impurity / по падению качества при перестановке / значения Шепли |
| Blending / Stacking | мета-модель на hold-out / на OOF-метапризнаках |

$$
\operatorname{Var}\Big(\frac1T\sum_{t=1}^T b_t\Big)=\rho\sigma^2+\frac{1-\rho}{T}\sigma^2,\qquad
P_{\text{err}}^{\text{3 голоса}}=3p^2-2p^3,\qquad P(\text{OOB})=(1-\tfrac1\ell)^\ell\approx0.368
$$

<summary><b>1. Что такое ансамбль</b></summary>

**Ансамбль** (ensemble, multiple classifier system) — алгоритм, состоящий из нескольких **базовых алгоритмов**
(base learners) и **мета-алгоритма**, объединяющего их ответы:

$$
a(x) = M\big(b_1(x), \dots, b_T(x)\big) .
$$

Простейшие ансамбли: **усреднение** в регрессии $a(x) = \frac{1}{T}\sum_t b_t(x)$ и **комитет большинства** в
классификации $a(x) = \operatorname{mode}\big(b_1(x), \dots, b_T(x)\big)$. В бустинге базовые алгоритмы называют **слабыми** (weak learners).

**Почему это работает**

- **Регрессия:** если ответы $T$ моделей независимы с одинаковыми средним и дисперсией $\sigma^2$, дисперсия
  среднего — $\sigma^2/T$. С корреляцией $\rho$: $\rho\sigma^2 + \frac{1-\rho}{T}\sigma^2$ (вывод — см. раздел «1. Дисперсия среднего коррелированных моделей»).
- **Классификация:** три независимых классификатора с ошибкой $p$ дают ошибку комитета $3p^2 - 2p^3$ — при малых
  $p$ очень мала, при $p = 0.3$ — 0.216. В общем случае (неравенство Хёфдинга) ошибка падает **экспоненциально**
  с числом алгоритмов (вывод — см. раздел «2. Ошибка комитета большинства»).
- **Но это в теории:** на практике алгоритмы не независимы — учатся на одном таргете, решают одну задачу,
  часто это одна модель. Поэтому главное — **разнообразие**: пусть алгоритмы ошибаются, но **по-разному**.

**Три обоснования ансамблей**

| Обоснование | Смысл |
|---|---|
| **Статистическое** | ошибка усреднения может быть меньше ошибки каждого |
| **Вычислительное** | обучение = оптимизация с локальными минимумами; ансамбль «распараллеливает» поиск |
| **Функциональное** (representational) | ансамбль представляет функции, недоступные базовым алгоритмам |

**Что варьируют для разнообразия**

| Что меняем | Метод |
|---|---|
| Обучающую выборку | бэггинг, пэстинг, CV-комитеты |
| Признаки | случайные подпространства, случайный лес |
| Целевой вектор | бустинг, ECOC, преобразования $f(y)$ |
| Модели | стекинг, блендинг, голосование разных моделей |
| Алгоритмы внутри модели | гиперпараметры, инициализации, snapshot-ансамбли, random seed в RF |

<summary><b>2. Комитеты и способы усреднения</b></summary>

| Способ | Формула / идея |
|---|---|
| Голосование по большинству (hard voting) | класс, за который больше голосов |
| Мягкое голосование (soft voting) | среднее вероятностей, затем argmax |
| Комитет единогласия (бинарная задача) | «1», только если все сказали «1» — или «тревога при малейшем подозрении»: «1», если хоть один сказал «1» |
| Взвешенное усреднение | $\sum_t w_t b_t(x)$, $\sum w_t = 1$; веса подбирают на валидации |
| Обобщения среднего | геометрическое, гармоническое, среднее по Колмогорову $f^{-1}\big(\frac1T\sum f(b_t)\big)$ |
| **Ранговое усреднение** | усредняем ранги прогнозов — под AUC, где важен лишь порядок |
| Feature-Weighted Linear Stacking | веса моделей зависят от признаков объекта |

```python
from sklearn.ensemble import VotingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.naive_bayes import GaussianNB
from sklearn.ensemble import RandomForestClassifier

eclf = VotingClassifier(
    estimators=[("lr", LogisticRegression(max_iter=1000)), ("rf", RandomForestClassifier(n_estimators=50)),
                ("gnb", GaussianNB())],
    voting="soft",          # 'hard' — по большинству, 'soft' — по сумме вероятностей
    weights=None)           # веса алгоритмов
eclf.fit(X, y)
```

<summary><b>3. Бэггинг и его родственники</b></summary>

**Bagging** (bootstrap aggregating): каждый базовый алгоритм обучается на **бутстрэп-выборке** (с возвращением,
того же размера), ответы усредняются.

```
для t = 1..T:
    X_t = бутстрэп-выборка из X
    b_t = обучить базовый алгоритм на X_t
a(x) = среднее b_t(x)  (регрессия) / голосование (классификация)
```

- Каждый алгоритм видит ~**63%** уникальных объектов; остальные ~37% — **out-of-bag (OOB)**.
- По OOB-объектам строим **OOB-прогноз** и **OOB-ошибку** — бесплатная оценка качества, похожая на CV.
- Бэггинг — процедура **снижения дисперсии**: работает для гибких моделей с высокой дисперсией
  (глубокие деревья, kNN с малым $k$), почти не помогает стабильным (логистическая регрессия).
- Смещение не уменьшает.

| Вариант | Как выбираем подвыборку |
|---|---|
| **Бэггинг** | объекты с возвращением (бутстрэп) |
| **Пэстинг** (Pasting) | объекты без возвращения (случайная подвыборка) |
| **Случайные подпространства** (Random Subspaces) | случайное подмножество **признаков** |
| **Случайные патчи** (Random Patches) | одновременно объекты **и** признаки |
| **Cross-Validated Committees** | $k$ моделей, каждая на $k-1$ фолдах |

```python
from sklearn.ensemble import BaggingClassifier
from sklearn.svm import SVC

clf = BaggingClassifier(estimator=SVC(),     # базовая модель (раньше: base_estimator)
                        n_estimators=10,     # число алгоритмов в ансамбле
                        max_samples=1.0,     # размер подвыборки (доля или число)
                        max_features=1.0,    # доля признаков → random subspaces / patches
                        bootstrap=True,      # с возвращением (False → пэстинг)
                        bootstrap_features=False,
                        oob_score=True,      # считать OOB-оценку
                        warm_start=False)    # дообучать существующий ансамбль
clf.fit(X, y); clf.oob_score_
```

<summary><b>4. Случайный лес (Random Forest)</b></summary>

**Случайный лес** (Лео Брейман, 2001) = **бэггинг деревьев + случайный выбор признаков при каждом расщеплении**.
Качество одного дерева низкое, у ансамбля — высокое.

**Алгоритм:**
1. Для каждого дерева берём подвыборку размера `max_samples` (обычно бутстрэп).
2. Строим дерево:
   - при **каждом** расщеплении просматриваем только `max_features` случайных признаков;
   - дерево строится, как правило, **до исчерпания выборки** (без прунинга).
3. Ответ леса:
   - **регрессия** — среднее арифметическое ответов деревьев;
   - **классификация** — по большинству (вероятность = доля деревьев) или, как в sklearn, среднее вероятностей
     в листьях деревьев, затем порог / максимум.

Автоматически получаем: **рейтинг признаков** (`feature_importances_`), **уверенность** в ответе (дисперсия
ответов деревьев), **OOB-оценку** качества.

**Гиперпараметры: что и как настраивать**

| Гиперпараметр | Влияние | Рекомендация |
|---|---|---|
| `n_estimators` | больше деревьев → стабильнее, лес **не переобучается** от числа деревьев | «чем больше, тем лучше» — пока хватает времени; `warm_start=True` для наращивания |
| `max_features` | **самый важный**: меньше → разнообразнее деревья, но слабее каждое; зависимость **унимодальная** | настраивать в первую очередь; по умолчанию $\sqrt d$ (классификация), $d/3$ у Бреймана (регрессия; в sklearn — все признаки); зависит от числа шумовых признаков, перенастраивать при добавлении признаков |
| `max_samples` | больше → однотипнее деревья, дольше | часто «чем больше, тем лучше»; не в первую очередь |
| `criterion` | gini / entropy — на практике разницы почти нет | по умолчанию gini |
| `max_depth` | обычно **без ограничений** | неглубокие деревья — при выбросах или очень больших данных |
| `min_samples_leaf`, `min_samples_split` | сложность деревьев | несколько объектов в листе (1 — классификация, 5 — регрессия); чуть подкорректировать |
| `class_weight` | дисбаланс классов | `'balanced'`, `'balanced_subsample'` |

На Kaggle часто суммируют леса с разными `max_features`.

```python
from sklearn.ensemble import RandomForestClassifier
rf = RandomForestClassifier(n_estimators=500, max_features="sqrt", min_samples_leaf=1,
                            bootstrap=True, oob_score=True, n_jobs=-1, random_state=0)
rf.fit(X_train, y_train)
rf.oob_score_                             # accuracy по OOB
rf.oob_decision_function_[:, 1]           # OOB-вероятности → можно посчитать OOB ROC-AUC
```

**Важность признаков**

| Метод | Как считается | Плюсы | Минусы |
|---|---|---|---|
| **MDI** (Mean Decrease in Impurity) | суммарное уменьшение impurity по сплитам признака, среднее по деревьям | быстро, «бесплатно» | на обучении; завышает признаки с большим числом уникальных значений; смещён при корреляции |
| **MDA** / permutation importance | падение качества при перемешивании признака (на тесте / OOB) | реальный вклад в качество | дорого; делит важность коррелированных признаков |
| **SHAP** | значения Шепли — вклад признака в прогноз каждого объекта | локальные и глобальные объяснения, знак эффекта | дороже; нужна библиотека `shap` |

На практике: MDI — быстрая отбраковка явно неинформативных признаков; MDA — честная оценка вклада в качество;
SHAP — детальный анализ и интерпретация (формулы — см. раздел «5. Важность признаков: MDI, MDA, SHAP»).

```python
from sklearn.inspection import permutation_importance
import shap

perm = permutation_importance(rf, X_test, y_test, n_repeats=10, scoring="roc_auc", n_jobs=-1)
explainer = shap.TreeExplainer(rf)
sv = explainer(X_test.iloc[:500])
shap.plots.beeswarm(sv[:, :, 1])          # для классификатора — значения для класса 1
```

**Extra Trees (экстремально рандомизированные деревья)**

- **Нет бутстрэпа** — каждое дерево видит всю выборку;
- для каждого из `max_features` признаков генерируется **случайный порог**, выбирается лучшая из этих пар;
- обучается быстрее RF (не перебирает все пороги); чуть хуже RF, когда много шумовых признаков.

```python
from sklearn.ensemble import ExtraTreesClassifier
ExtraTreesClassifier(n_estimators=500, max_features="sqrt", n_jobs=-1)
```

**Ещё про лес**

- **Proximity**: чем чаще два объекта попадают в один лист, тем они ближе — обученная метрика близости.
- **Synthetic RF**: стекинг лесов с разными `min_samples_leaf` на OOB-прогнозах (Ishwaran, Malley, 2014).
- Леса наследуют главный недостаток деревьев — **плохи для экстраполяции**.
- **Isolation Forest** — лес случайных деревьев для поиска аномалий (тема [10](../10_anomaly_detection/README.md));
  в семинаре его использовали для чистки выбросов перед обучением леса (`contamination=0.01`).

<summary><b>5. Стекинг и блендинг</b></summary>

**Стекинг** (stacking, Д. Волперт, 1992): вместо фиксированного усреднения обучаем **мета-алгоритм** на ответах
базовых алгоритмов (метапризнаках).

**Наивный стекинг неправилен**: если обучать мета-алгоритм на ответах базовых моделей **на их же обучающей
выборке**, метки используются дважды → переобучение (базовый 1NN на обучении воспроизводит метки,
мета-алгоритм ему «доверяет», а на тесте 1NN ошибается).

**Блендинг (blending) — простейшая форма**

1. Делим обучение на две части. 2. Базовые алгоритмы учим на первой. 3. Их ответы на второй (отложенной) части —
обучающие метапризнаки для мета-алгоритма. 4. На тесте: базовые алгоритмы → метапризнаки → мета-алгоритм.

Термин ввели победители конкурса Netflix. Недостаток — используется не вся выборка (можно усреднить
несколько блендингов). Сейчас блендингом часто называют просто выпуклую комбинацию алгоритмов.

**Стекинг на фолдах**

1. Делим обучение на $k$ фолдов; метапризнаки каждого фолда — ответы модели, обученной на остальных фолдах
   (**out-of-fold**, `cross_val_predict`).
2. Мета-алгоритм учится на OOF-метапризнаках всей обучающей выборки.
3. Метапризнаки теста — ответы базовых моделей, обученных на всём обучении (или среднее фолдовых моделей).

Тонкость: метапризнаки на обучении и тесте немного по-разному распределены → регуляризация мета-модели,
нормальный шум к метапризнакам, усреднение по разным разбиениям.

**Практика стекинга:**
- нужны достаточно большие выборки; хорош для алгоритмов **разной природы** (у каждого может быть своё признаковое пространство);
- пример: регрессоры + RF → устойчивость к аномальным значениям признаков;
- мета-алгоритм должен минимизировать нужную целевую функцию (log_regs + log_reg может не справиться с log loss);
- базовые алгоритмы сильно не оптимизируют, иногда учат не на сам таргет; добавляют модели других функционалов и даже кластеризаторы;
- **многоуровневый стекинг** оправдан только в соревнованиях;
- новые гиперпараметры: число фолдов, уровень шума.

```python
from sklearn.ensemble import StackingClassifier, RandomForestClassifier, ExtraTreesClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

stack = StackingClassifier(
    estimators=[("rf", RandomForestClassifier(300, n_jobs=-1)),
                ("et", ExtraTreesClassifier(300, n_jobs=-1)),
                ("knn", make_pipeline(StandardScaler(), KNeighborsClassifier(15)))],
    final_estimator=LogisticRegression(),
    cv=5,                         # OOF-метапризнаки
    stack_method="predict_proba",
    passthrough=False)            # True — добавить исходные признаки к метапризнакам
stack.fit(X_train, y_train)
```

**Свой стекинг регрессии (по мотивам ДЗ)**

```python
import numpy as np
from sklearn.base import clone
from sklearn.model_selection import KFold, cross_val_predict

class MyStackingRegressor:
    def __init__(self, base_models, meta_model, n_splits=5, random_state=0):
        self.base_models, self.meta_model = base_models, meta_model
        self.cv = KFold(n_splits, shuffle=True, random_state=random_state)

    def fit(self, X, y):
        Z = np.column_stack([cross_val_predict(clone(m), X, y, cv=self.cv) for m in self.base_models])  # OOF
        self.meta_ = clone(self.meta_model).fit(Z, y)
        self.base_ = [clone(m).fit(X, y) for m in self.base_models]      # доучиваем на всём train
        return self

    def predict(self, X):
        Z = np.column_stack([m.predict(X) for m in self.base_])
        return self.meta_.predict(Z)
```

В ДЗ (Wine Quality, 6 базовых моделей: Ridge, LASSO, SVR, kNN, RF, Extra Trees) стекинг оказался лучше
блендинга и одиночного леса — благодаря разнообразию моделей и автоматическому подбору весов.

<summary><b>6. Бустинг и другие ансамбли (кратко)</b></summary>

- **Бустинг**: базовые алгоритмы строятся **последовательно**, каждый исправляет ошибки предыдущих
  (forward stagewise additive modeling). Подробно — тема [09](../09_gradient_boosting/README.md).
- **ECOC** (error-correcting output coding): кодируем классы бинарными кодами, учим по классификатору на каждый
  бит, декодируем по ближайшему коду.
- **Однородные ансамбли**: рекурсия «мета-алгоритм(базовые)» + общая оптимизация — по сути нейросети.

| | Параллельные ансамбли | Последовательные ансамбли |
|---|---|---|
| Как строятся | независимо | каждый с учётом предыдущих |
| Базовые модели | сложные (low bias, high variance) | простые (high bias) |
| Что уменьшают | **variance** | **bias** (и variance) |
| Примеры | бэггинг, RF, Extra Trees | AdaBoost, градиентный бустинг |

</details>

<details>
<summary><b>Типичные ошибки</b></summary>

- Бэггинг стабильных моделей (линейных) и ожидание большого прироста.
- Ограничение глубины деревьев в RF «как у одного дерева» — лесу нужны глубокие деревья.
- Наивный стекинг на in-sample предсказаниях.
- Доверие MDI-важностям признаков с большим числом уникальных значений (ID, timestamp).
- Ожидание экстраполяции от леса.

</details>

**Математика и выводы**

<details>
<summary><b>1. Дисперсия среднего коррелированных моделей</b></summary>

Пусть $b_1, \dots, b_T$ — ответы базовых регрессоров на объекте $x$, $\mathbb{E}b_t = \mu$, $\operatorname{Var}b_t = \sigma^2$,
$\operatorname{corr}(b_s, b_t) = \rho$ при $s \ne t$. Для ансамбля $a = \frac{1}{T}\sum_t b_t$:

$$
\operatorname{Var}a = \frac{1}{T^2}\Big(\sum_t\operatorname{Var}b_t + \sum_{s\ne t}\operatorname{cov}(b_s, b_t)\Big)
= \frac{1}{T^2}\big(T\sigma^2 + T(T-1)\rho\sigma^2\big) = \rho\sigma^2 + \frac{1-\rho}{T}\sigma^2 .
$$

- Независимые модели ($\rho = 0$): дисперсия падает в $T$ раз (слайд «если ответы регрессоров — независимые
  случайные величины с одинаковым матожиданием и дисперсией»).
- Коррелированные: с ростом $T$ дисперсия стремится к $\rho\sigma^2$, а не к 0. **Уменьшать $\rho$ так же важно,
  как увеличивать $T$** — отсюда вся «рандомизация» в бэггинге и случайном лесе.
- Смещение: $\mathbb{E}a = \mu$ — такое же, как у одной модели. Усреднение помогает моделям с **низким
  смещением и высокой дисперсией** (глубокие деревья), но почти бесполезно для стабильных моделей
  (логистическая регрессия в семинаре: ROC-AUC 0.864 у одной модели и почти столько же у бэггинга).

</details>

<details>
<summary><b>2. Ошибка комитета большинства</b></summary>

**Три независимых классификатора**, каждый ошибается с вероятностью $p$. Комитет ошибается, если
ошиблись хотя бы двое:

$$
P_{\text{err}} = 3p^2(1-p) + p^3 = 3p^2 - 2p^3 .
$$

При $p = 0.1$: $0.028$; при $p = 0.3$: $0.216$ (почти в полтора раза меньше); при малых $p$ — порядка $3p^2$,
«очень мала»; при $p = 0.5$ — те же 0.5.

**Общий случай.** $T$ независимых классификаторов с ошибкой $p < \frac12$; число ошибшихся
$S \sim \text{Bin}(T, p)$, комитет ошибается при $S \ge T/2$. По **неравенству Хёфдинга**

$$
P\Big(\frac{S}{T} - p \ge \frac12 - p\Big) \le \exp\Big(-2T\big(\tfrac12 - p\big)^2\Big),
$$

ошибка **экспоненциально** падает с ростом $T$. Но это в теории: на практике классификаторы не независимы —
учатся на одном таргете, решают одну задачу, часто это одна и та же модель.

**Зачем разнообразие** (пример со слайда: 10 объектов, `1` — ошибка на объекте, у каждого из трёх
алгоритмов точность $q = 0.6$):
- **одинаковые** `1111000000` ×3 → точность комитета $q_{ens} = 0.6$ (ничего не выиграли);
- **похожие** `1111000000`, `1110100000`, `1101100000` → большинство ошибается на 5 объектах, $q_{ens} = 0.5$ —
  стало **хуже**;
- **разные** `1111000000`, `0000111100`, `1100000011` → большинство ошибается только на первых двух, $q_{ens} = 0.8$.

Алгоритмы должны ошибаться **по-разному**, чтобы ошибки одних компенсировались правильными ответами других.

</details>

<details>
<summary><b>3. Бэггинг и OOB</b></summary>

**Bagging** (bootstrap aggregating): $a(x) = \frac{1}{T}\sum_t b_t(x)$, где $b_t$ обучен на бутстрэп-выборке $X_t$.

- В бутстрэп-выборку попадает ≈ 63.2% уникальных объектов ([вывод](../05_validation/README.md)),
  остальные ≈ 36.8% — **out-of-bag** для этой модели.
- **OOB-прогноз** объекта $x_i$ — среднее по моделям, для которых $x_i$ был OOB:

$$
a_{\text{OOB}}(x_i) = \frac{1}{|T_i|}\sum_{t \in T_i} b_t(x_i), \qquad T_i = \lbrace t: x_i \notin X_t\rbrace,\quad |T_i| \approx 0.368\,T .
$$

- OOB-ошибка — «бесплатная» оценка качества, похожая на CV. Она слегка **пессимистична**: каждый OOB-прогноз —
  ансамбль лишь из ≈ 37% деревьев (в семинаре: OOB ROC-AUC 0.882 против теста 0.890).

**Почему бэггинг помогает неустойчивым алгоритмам** (Breiman, 1996). Пусть $\varphi(x, D)$ — прогноз модели,
обученной на $D$, а $\varphi_A(x) = \mathbb{E}_D\varphi(x, D)$ — «агрегированный» прогноз. Для квадратичной ошибки
(неравенство Йенсена)

$$
\mathbb{E}_D\big(y - \varphi(x, D)\big)^2 \ge \big(y - \varphi_A(x)\big)^2 ,
$$

причём выигрыш равен $\operatorname{Var}_D\varphi(x, D)$ — он велик именно для неустойчивых процедур (деревья,
нейросети), и близок к нулю для устойчивых (kNN с большим $k$, линейные модели). Бэггинг приближает
$\varphi_A$, заменяя распределение выборок бутстрэпом.

</details>

<details>
<summary><b>4. Случайный лес: сила и корреляция</b></summary>

**Random Forest** = бэггинг деревьев + на каждом сплите выбирается лучший сплит лишь среди `max_features`
случайных признаков. Это уменьшает корреляцию $\rho$ между деревьями.

**Оценка Бреймана (2001).** Для классификации определим отступ ансамбля
$mr(x, y) = P_\Theta(h(x,\Theta) = y) - \max_{j\ne y}P_\Theta(h(x,\Theta) = j)$, **силу** $s = \mathbb{E}_{x,y}\,mr(x,y)$
и среднюю корреляцию $\bar\rho$ «сырых отступов» деревьев. Тогда ошибка обобщения

$$
PE^* \le \frac{\bar\rho\,(1 - s^2)}{s^2} .
$$

Нужно одновременно: **сильные** деревья (глубокие, большой `max_features`) и **слабо коррелированные**
(маленький `max_features`). Оба зависят от `max_features` в разные стороны → зависимость качества от него
**унимодальна** (слайд). Типичные значения: $\sqrt d$ для классификации, $d/3$ для регрессии (у Бреймана;
в sklearn по умолчанию для регрессии — все признаки, `1.0`).

**Лес не переобучается от числа деревьев.** По усиленному закону больших чисел при $T \to \infty$ ошибка
леса сходится к ошибке «бесконечного» ансамбля $\mathbb{E}_\Theta h(x, \Theta)$; добавление деревьев уменьшает
дисперсию оценки этого среднего и не увеличивает переобучение («чем больше, тем лучше» — ограничение
только по времени). Переобучиться лес может из-за слишком глубоких деревьев на шумных данных.

**Extra Trees** (Geurts et al., 2006): без бутстрэпа; на каждом сплите для каждого из `max_features`
признаков генерируется **случайный порог**, выбирается лучшая пара. Ещё ниже корреляция и дисперсия,
чуть выше смещение; быстрее (нет сортировки). Хуже RF, когда много шумовых признаков.

**Proximity.** $\text{prox}(x_i, x_j) = \frac{1}{T}\sum_t[\text{leaf}_t(x_i) = \text{leaf}_t(x_j)]$ — доля деревьев, где объекты
попали в один лист. Обученная лесом мера близости: $1 - \text{prox}$ можно использовать для кластеризации,
визуализации (MDS), заполнения пропусков, поиска выбросов.

</details>

<details>
<summary><b>5. Важность признаков: MDI, MDA, SHAP</b></summary>

**MDI** (по дереву $t$ и усреднение по лесу):

$$
\text{MDI}_j^{(t)} = \sum_{v:\,\text{сплит по } j}\frac{|R_v|}{|R|}\Delta H(R_v),\qquad \text{MDI}_j = \frac{1}{T}\sum_t\text{MDI}_j^{(t)} .
$$

Быстрая, но смещена к признакам с большим числом уникальных значений и считается по обучению.

**MDA / permutation importance:** $\text{MDA}_j = \text{Err}_{\text{perm}, j} - \text{Err}_{\text{base}}$, усреднённая по повторам
перестановки; у Бреймана — на OOB-объектах каждого дерева. Измеряет **реальный вклад в качество**. При
сильно коррелированных признаках перестановка одного создаёт нереалистичные объекты, и важность
«делится» между коррелированными признаками.

**SHAP.** Значение Шепли признака $j$ для объекта $x$ — средний вклад признака по всем порядкам «добавления»
признаков:

$$
\phi_j(x) = \sum_{S \subseteq F\setminus\lbrace j\rbrace}\frac{|S|!\,(|F| - |S| - 1)!}{|F|!}\Big(v(S \cup \lbrace j\rbrace) - v(S)\Big),
$$

где $v(S) = \mathbb{E}[f(X) \mid X_S = x_S]$ — прогноз модели при известных признаках $S$. Единственный способ
распределить «выигрыш», удовлетворяющий аксиомам: **эффективность** $\sum_j\phi_j(x) = f(x) - \mathbb{E}f(X)$,
симметрия, «болвана» (бесполезный признак → 0), аддитивность. Наивно — $O(2^{|F|})$; **TreeSHAP** для деревьев
считает точно за $O(TLD^2)$ ($L$ листьев, $D$ глубина). Пример со слайда семинара: прибыль компании из трёх
человек делится по средним вкладам при всех порядках присоединения.

</details>

<details>
<summary><b>6. Стекинг</b></summary>

**Наивный стекинг** (обучаем мета-алгоритм на ответах базовых алгоритмов **на той же обучающей выборке**)
переобучается: метки используются дважды. Крайний случай — базовый 1NN: на обучении он воспроизводит
истинные метки, мета-алгоритм учится ему полностью доверять, а на тесте 1NN уже ошибается.

**Правильно — out-of-fold метапризнаки** (Wolpert, 1992):
1. делим обучение на $k$ фолдов; для каждого фолда обучаем базовый алгоритм на остальных и предсказываем этот фолд →
   метапризнаки на всём обучении (OOF);
2. мета-алгоритм обучаем на OOF-матрице $Z \in \mathbb{R}^{\ell\times M}$;
3. базовые алгоритмы переобучаем на всём обучении (или усредняем $k$ фолдовых моделей) и строим метапризнаки теста.

**Тонкость:** метапризнаки на обучении (OOF, модели видели $\frac{k-1}{k}$ данных) и на тесте (модель на всех данных)
распределены немного по-разному. Лечится регуляризацией мета-модели, шумом к метапризнакам, усреднением
по нескольким разбиениям.

**Блендинг** — простейший стекинг: метапризнаки строятся на одном отложенном куске (hold-out). Проще, нет
утечек, но мета-модель видит не всю выборку.

**Оптимальные веса линейного блендинга двух моделей**

Ошибки моделей $e_1, e_2$ с дисперсиями $\sigma_1^2, \sigma_2^2$ и ковариацией $\sigma_{12}$ (средние ошибок ≈ 0).
Ошибка смеси $w e_1 + (1-w)e_2$ имеет дисперсию $w^2\sigma_1^2 + (1-w)^2\sigma_2^2 + 2w(1-w)\sigma_{12}$; минимум по $w$:

$$
w^* = \frac{\sigma_2^2 - \sigma_{12}}{\sigma_1^2 + \sigma_2^2 - 2\sigma_{12}} .
$$

Даже **худшая** модель получает положительный вес, если она слабо коррелирована с лучшей ($\sigma_{12} < \sigma_2^2$).
При $\sigma_{12} \to \sigma_1\sigma_2$ (сильная корреляция) выигрыш исчезает. Бреймановский «stacked regression»
рекомендует неотрицательные веса (`nnls`) для устойчивости.

**Ранговое усреднение** под AUC: усредняем не вероятности, а ранги прогнозов (AUC зависит только от порядка;
так разные шкалы моделей не мешают).

</details>

<details>
<summary><b>7. Три обоснования ансамблей (Dietterich, 2000)</b></summary>

1. **Статистическое:** при малых данных многие гипотезы одинаково хороши на обучении; усреднение снижает
   риск выбрать «неудачную» → меньше дисперсия.
2. **Вычислительное:** обучение — невыпуклая оптимизация с локальными минимумами (деревья, нейросети);
   запуски из разных начальных точек и их усреднение приближают лучшее решение.
3. **Функциональное (representational):** истинная зависимость может не лежать в классе базовых моделей,
   но лежать в классе их взвешенных сумм (сумма «ступенчатых» деревьев аппроксимирует гладкую функцию,
   сумма линейных классификаторов даёт нелинейную границу).

</details>

<details>
<summary>Почему бэггинг не помогает линейной регрессии?</summary>

она стабильна (низкая дисперсия); бэггинг снижает только variance.

<summary>Переобучается ли RF при росте `n_estimators`?</summary>

нет, ошибка сходится; переобучаться могут сами деревья.

</details>

<details>
<summary>Зачем `max_features` в RF?</summary>

декорреляция деревьев: дисперсия ансамбля упирается в $\rho\sigma^2$.

</details>

<details>
<summary>Почему наивный стекинг переобучается?</summary>

мета-модель учится на in-sample прогнозах; нужны OOF-метапризнаки.

</details>

<details>
<summary>MDI vs permutation importance?</summary>

MDI на train и смещён к высококардинальным признакам; MDA — на валидации, честнее.

</details>

<summary><b>Дополнительно: детали</b></summary>

- Ошибка комитета из $T$ независимых классификаторов падает экспоненциально (Хёфдинг): $\le e^{-2T(1/2-p)^2}$.
- Оценка Бреймана: $PE^*\le\bar\rho(1-s^2)/s^2$ — нужны сильные **и** слабо коррелированные деревья.
- Оптимальный вес блендинга двух моделей $w^*=\frac{\sigma_2^2-\sigma_{12}}{\sigma_1^2+\sigma_2^2-2\sigma_{12}}$ — слабая, но некоррелированная модель полезна.
- SHAP: $\sum_j\phi_j(x)=f(x)-\mathbb{E}f(X)$; TreeSHAP считает точно за полиномиальное время.

</details>

<summary><b>Примеры кода (с результатами запуска)</b></summary>

Запустить их можно в ноутбуке [`cheatsheet.ipynb`](../../cheatsheet.ipynb).

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import BaggingClassifier, RandomForestClassifier, ExtraTreesClassifier
from sklearn.metrics import roc_auc_score

X, y = make_classification(n_samples=3000, n_features=30, n_informative=8, flip_y=0.05, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0)
models = {
    "Одно дерево":   DecisionTreeClassifier(random_state=0),
    "Бэггинг 200":   BaggingClassifier(DecisionTreeClassifier(), n_estimators=200, n_jobs=-1, random_state=0),
    "RF 200":        RandomForestClassifier(n_estimators=200, oob_score=True, n_jobs=-1, random_state=0),
    "ExtraTrees 200": ExtraTreesClassifier(n_estimators=200, n_jobs=-1, random_state=0),
}
for name, m in models.items():
    m.fit(X_tr, y_tr)
    print(f"{name:15} test ROC-AUC = {roc_auc_score(y_te, m.predict_proba(X_te)[:, 1]):.3f}")
rf = models["RF 200"]
print(f"RF OOB ROC-AUC = {roc_auc_score(y_tr, rf.oob_decision_function_[:, 1]):.3f}  (оценка без отдельной валидации)")
```

Результат запуска:

```text
Одно дерево     test ROC-AUC = 0.852
Бэггинг 200     test ROC-AUC = 0.950
RF 200          test ROC-AUC = 0.953
ExtraTrees 200  test ROC-AUC = 0.952
RF OOB ROC-AUC = 0.969  (оценка без отдельной валидации)
```

```python
# Стекинг на OOF-метапризнаках
from sklearn.ensemble import StackingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
stack = StackingClassifier(
    estimators=[("rf", RandomForestClassifier(200, n_jobs=-1, random_state=0)),
                ("knn", make_pipeline(StandardScaler(), KNeighborsClassifier(25))),
                ("lr", make_pipeline(StandardScaler(), LogisticRegression()))],
    final_estimator=LogisticRegression(), cv=5, stack_method="predict_proba")
stack.fit(X_tr, y_tr)
print(f"Stacking test ROC-AUC = {roc_auc_score(y_te, stack.predict_proba(X_te)[:, 1]):.3f}")
```
