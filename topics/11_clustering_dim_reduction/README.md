## Часть A. Снижение размерности

**Общий смысл:** перевести $d$ признаков в $k < d$ так, чтобы информация о различиях и зависимостях между
объектами сохранилась как можно лучше. Применения:
- визуализация: $d \to 2$ (реже 3);
- ускорение обучения моделей;
- повышение качества (меньше шума и мультиколлинеарности, тема [06](../06_bias_variance/README.md)).

### A.1. PCA — метод главных компонент

**Идея:** при проекции в $k$-мерное пространство дисперсия вдоль каждой новой оси должна быть максимальной —
чтобы объекты оставались различимыми (плохой пример: две разные точки 2D проецируются в одну точку 1D).
Бонус: при максимальном разбросе проекций **сумма квадратов длин перпендикуляров** до подпространства
минимальна — это строгий факт ([оба вывода](deep.md#6-pca-два-эквивалентных-вывода)).

- **Главные компоненты** — направления новых осей = собственные векторы ковариационной матрицы $S$;
  дисперсия вдоль компоненты = соответствующее собственное значение.
- **Объяснённая дисперсия** (`explained_variance_ratio_`): по накопленной кривой выбирают $k$ (например, ≥ 95%).
- **Обратное преобразование** (`inverse_transform`) — аппроксимация объекта $k$ компонентами. «Eigenfaces» на
  Olivetti faces: 4096 пикселей → 150 компонент сохраняют > 96% дисперсии; храним $400\times150$ + $150$ векторов
  по 4096 вместо $400\times4096$ — сжатие более чем в 2.5 раза.

> ⚠️ **Перед PCA признаки нормируют** — иначе дисперсия определяется единицами измерения. Исключение —
> разреженные признаки вроде tf-idf, они уже «нормированы». Выбросы искажают компоненты — анализировать/удалять.

| Плюсы PCA | Минусы PCA |
|---|---|
| уменьшает переобучение в многомерных данных | ловит только **линейные** зависимости |
| убирает скоррелированность признаков (компоненты ортогональны) | новые признаки плохо интерпретируются |
| быстрый на больших данных, детерминированный | чувствителен к масштабу и выбросам |
| почти не требует настройки (кроме `n_components`) | |

### A.2. t-SNE

**Идея:** сохранить не глобальную дисперсию, а **локальную** структуру: похожие (близкие) объекты должны остаться
близкими. Считаем вероятности близости пар в исходном и новом пространстве и минимизируем расхождение
(KL) между распределениями ([формулы](deep.md#7-t-sne)).

- **`perplexity`** — сколько точек считать «соседями»; рекомендуемый диапазон **5–50**; визуализация сильно от него зависит.
- Плюсы: сохраняет локальную структуру и нелинейные зависимости.
- Минусы: долго (для больших $d$ сначала PCA до ~50 признаков); **не сохраняет форму кластеров и расстояния между
  ними**; новые признаки неинтерпретируемы; недетерминирован; **нет `transform`** — нельзя «обучить» и применить к новым данным.

### A.3. UMAP

Появился в 2018: скорость, близкая к PCA, сохранение локальной структуры как у t-SNE + старается сохранить и
**глобальную**. Больше других подходит как предобработка для кластеризации.
Минусы: не в sklearn (`umap-learn`), может требовать много RAM, недетерминирован, много гиперпараметров
(`n_neighbors` — локальное vs глобальное, `min_dist` — плотность упаковки).

### A.4. Isomap

Строим граф ближайших соседей, считаем кратчайшие пути (**геодезические** расстояния — «вдоль многообразия»),
затем применяем **MDS** (Multidimensional Scaling). Хорошо передаёт взаимное расположение, сохраняет и локальную,
и глобальную структуру, учитывает нелинейность. Минусы: небыстрый, есть параметры; желательно очистить от шума.

| Метод | Линейный | Сохраняет | Новые данные (`transform`) | Скорость | Детерминирован |
|---|---|---|---|---|---|
| PCA | да | глобальную дисперсию | да | очень быстро | да |
| t-SNE | нет | локальную структуру | **нет** | медленно | нет |
| UMAP | нет | локальную + частично глобальную | да | быстро | нет |
| Isomap | нет | геодезические расстояния | да | медленно | да |

```python
from sklearn.decomposition import PCA
from sklearn.manifold import TSNE, Isomap
from sklearn.preprocessing import StandardScaler
# from umap import UMAP

X_s = StandardScaler().fit_transform(X)
pca = PCA(n_components=0.95).fit(X_s)            # столько компонент, чтобы объяснить 95% дисперсии
pca.n_components_, pca.explained_variance_ratio_.cumsum()
X_tsne = TSNE(n_components=2, perplexity=30, random_state=0).fit_transform(X_s)
X_iso = Isomap(n_neighbors=10, n_components=2).fit_transform(X_s)
# X_umap = UMAP(n_neighbors=15, min_dist=0.1).fit_transform(X_s)
```

## Часть B. Кластеризация

**Кластеризация** — разбиение объектов на группы (кластеры) похожих объектов **без разметки**. Нет «правильного»
ответа: результат зависит от метрики, алгоритма и масштаба признаков (масштабировать обязательно, если признаки в
разных шкалах; в ДЗ с бинарными признаками «животных» масштабирование некритично).

### B.1. K-means

1. Выбрать $K$ начальных центров.
2. Отнести каждый объект к ближайшему центру.
3. Пересчитать центры как средние объектов кластеров.
4. Повторять 2–3 до стабилизации.

Минимизирует **инерцию** $\sum_k\sum_{x_i\in C_k}\|x_i - \mu_k\|^2$; сходится к локальному минимуму ([почему](deep.md#1-k-means-функционал-и-алгоритм-ллойда)).

- **Число кластеров $K$** задаётся заранее: перебор + метрика качества (силуэт), **метод локтя** по `inertia_`,
  визуальная оценка на 2D-проекции (t-SNE/PCA/Isomap), знание предметной области.
- **Инициализация** сильно влияет на результат (семинар: 20 запусков с `init='random'` дают заметно разную
  инерцию). **k-means++** — следующий центр выбирается с вероятностью $\propto$ квадрату расстояния до ближайшего
  выбранного; результат стабильнее. Плюс `n_init` — несколько запусков, лучший по инерции.
- Находит выпуклые «шарообразные» кластеры похожего размера; плохо — «луны», кольца, разные плотности; чувствителен к выбросам.

### B.2. Агломеративная (иерархическая) кластеризация

Начинаем с кластеров из одного объекта, на каждом шаге **сливаем два ближайших**. Результат — **дендрограмма**;
разрезая её на нужной высоте (`distance_threshold` / `n_clusters`, в plotly — `color_threshold`), получаем разбиение.

| `linkage` | Расстояние между кластерами | Поведение |
|---|---|---|
| `single` | между ближайшими точками | «цепочки», вытянутые кластеры, чувствителен к шуму |
| `complete` | между самыми далёкими | компактные кластеры |
| `average` | среднее по всем парам | компромисс |
| `ward` | прирост внутрикластерной дисперсии | сбалансированные кластеры (обычно лучший по умолчанию; в ДЗ «животные» — лучший) |

Плюс: видна **иерархия** (виды → классы животных). Минус: $O(\ell^2)$ памяти — для небольших данных.

### B.3. DBSCAN

Кластеры — области **высокой плотности**; точки, у которых в радиусе `eps` меньше `min_samples` соседей и которые
не прилегают к плотным областям, — **шум** (метка −1).
- не нужно задавать число кластеров; находит кластеры **любой формы**; выделяет выбросы (тема [10](../10_anomaly_detection/README.md));
- плохо работает, если кластеры разной плотности (решение — **HDBSCAN**); чувствителен к `eps` и масштабу.

Практика из семинара: на данных об общепите Москвы (координаты) DBSCAN находит **торговые центры** — гипотеза: в ТЦ
самое плотное скопление точек с едой. В ДЗ — места с наилучшим покрытием городского Wi-Fi (точки продублированы
по числу точек подключения; подобрано `eps ≈ 0.0002` в градусах, `min_samples = 8` → кластеры у метро, вокзалов,
ТЦ, парков). Порядок `eps` зависит от единиц: в градусах широты/долготы 0.001 ≈ 70–110 м.

### B.4. Другие методы

- **GaussianMixture** (EM) — мягкая кластеризация, эллиптические кластеры, выбор $K$ по BIC ([EM](deep.md#5-смесь-гауссиан-и-em-мягкая-кластеризация));
- **MeanShift** — поиск мод плотности; **Spectral clustering** — кластеризация по графу похожести (невыпуклые кластеры);
- **HDBSCAN** — иерархический DBSCAN для кластеров разной плотности.

### B.5. Оценка качества кластеризации

| Тип | Метрика | Смысл |
|---|---|---|
| Внутренняя | **Инерция** (WCSS) | компактность; монотонно падает с ростом $K$ → «локоть» |
| Внутренняя | **Силуэт** $\frac{b - a}{\max(a, b)}$ | $a$ — среднее расстояние до своих, $b$ — до ближайшего чужого кластера; от −1 до 1, больше — лучше |
| Внутренняя | Davies–Bouldin / Calinski–Harabasz | меньше / больше — лучше |
| Внешняя (есть разметка) | ARI, NMI | согласие с эталоном с поправкой на случайность |
| Внешняя | **BCubed** precision/recall/F | поэлементные: «склеивание» классов / «разрезание» класса ([формулы и код](deep.md#3-внешние-метрики-есть-эталонная-разметка)) |

В ДЗ (Zoo, 7 классов) разные критерии дали разные $K$: визуально и по локтю — 6, по BCubed — 8, по иерархии (Ward) — 7.
**Кластеризация — исследовательский инструмент**, итоговое $K$ выбирают с учётом задачи.

## Код

```python
import numpy as np
from sklearn.cluster import KMeans, AgglomerativeClustering, DBSCAN
from sklearn.metrics import silhouette_score, adjusted_rand_score
from scipy.cluster.hierarchy import dendrogram, linkage

# K-means: выбор K по силуэту и инерции
for k in range(2, 11):
    km = KMeans(n_clusters=k, init="k-means++", n_init=10, random_state=0).fit(X_s)
    print(k, round(km.inertia_, 1), round(silhouette_score(X_s, km.labels_), 3))

# Иерархическая
agg = AgglomerativeClustering(n_clusters=None, distance_threshold=0, linkage="ward").fit(X_s)
Z = linkage(X_s, method="ward")            # scipy: матрица слияний для dendrogram(Z)

# DBSCAN: eps по «локтю» расстояний до k-го соседа
from sklearn.neighbors import NearestNeighbors
k = 5
dist = np.sort(NearestNeighbors(n_neighbors=k).fit(X_s).kneighbors(X_s)[0][:, -1])   # смотрим излом графика
labels = DBSCAN(eps=0.5, min_samples=k).fit_predict(X_s)        # -1 — шум
```

## Типичные ошибки

- Кластеризовать без масштабирования признаков разной природы.
- Интерпретировать расстояния между кластерами и размеры кластеров на карте t-SNE.
- Применять t-SNE как препроцессинг для модели (нет `transform`, результат нестабилен).
- Выбирать $K$ по минимуму инерции (она всегда убывает).
- Ждать от K-means невыпуклых кластеров.
- Подбирать `eps` DBSCAN без учёта единиц измерения (градусы vs метры).
