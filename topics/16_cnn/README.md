## 1. Почему не полносвязная сеть

**Изображение** — трёхмерный тензор $C\times H\times W$ (цветное: 3 канала RGB; в PyTorch батч хранится как $N\times C\times H\times W$).

Линейный классификатор «вытянутой» картинки: 3 класса = 3 вектора весов; веса можно «прорешейпить» обратно в картинки —
видно, «как выглядят классы». Но:
- модель примитивна, линейное правило вряд ли подойдёт;
- объект в другом месте картинки — для неё **совсем другой вход** (пиксель $(3, 7)$ и $(9, 13)$ — независимые признаки);
- параметров чудовищно много (слой $224\times224\times3 \to 224\times224\times64$ — $4.8\cdot10^{11}$ весов).

Хотим: **поиск локальных паттернов** и **устойчивость к сдвигам**, небольшим поворотам, растяжениям.

**Свёрточные нейронные сети** (ConvNet, CNN) — нейросети для «равномерных сигналов» (изображения, звук, ряды).

## 2. Свёртка и её параметры

1-D свёртка: ядро (например, $[-1, 0, 1]$) скользит по сигналу, в каждой позиции — сумма поэлементных произведений.
В нейросетях это математически **корреляция** (ядро не отражается) — для обучаемых ядер неважно.

| Параметр | Что делает |
|---|---|
| **Ядро / фильтр** $c\times h\times w$ | глубина ядра = число каналов входа $C$; $h \ll H$, $w \ll W$ |
| **Шаг** (stride) | на сколько смещается ядро; $s = 2$ понижает разрешение; менее коррелированные выходы |
| **Отступ** (padding) | дополнение по краям: нулевой, константный, зеркальный (`reflect`), циклический — чтобы получить нужный размер |
| **Расширение** (dilation) | промежутки между точками ядра — увеличивает рецептивное поле без новых весов |

**Размер выхода:** $H_{\text{out}} = \big\lfloor\frac{H_{\text{in}} + 2p - d(k-1) - 1}{s}\big\rfloor + 1$ (проверено в семинаре на 6 случаях).

**Что делает свёртка** (классическое CV): размытие (blur), резкость (sharpen), **ядра Собеля** — границы разных направлений;
устраняют шум, находят границы, детектируют текстуры. **Раньше** свёртки конструировали вручную; **сейчас** параметры
настраиваются сами. Свёртку можно применять к изображениям **любого размера**.

**Несколько свёрток:** каждая даёт один «лист» (канал) выхода; $k$ свёрток — $k$-канальный выход. Свёрточный слой — 4D-массив
весов $C_{\text{out}}\times C_{\text{in}}\times h\times w$.

```python
import torch, torch.nn as nn
nn.Conv2d(in_channels=16, out_channels=33, kernel_size=(3, 5), stride=(2, 1), padding=(4, 2),
          dilation=(3, 1), groups=1, bias=True, padding_mode="zeros")   # 'reflect', 'replicate', 'circular'
# in_channels и out_channels должны делиться на groups
```

### Сколько параметров и операций

- Параметры: $C_{\text{out}}\cdot(C_{\text{in}}\cdot k\cdot k + 1)$; пример $3\to64$, $3\times3$: **1792**. Размер картинки не влияет — **разделение весов**.
- Операции: $H_{\text{out}}\cdot W_{\text{out}}\cdot C_{\text{out}}\cdot C_{\text{in}}\cdot k^2$; тот же слой на $224\times224$ — ≈ 87 млн умножений-сложений. На стоимость
  размер картинки влияет прямо → разрешение понижают по ходу сети.
- Это не оптимизация, а **другая модель**: мы заранее заявили, что признак не зависит от положения и локален.

### Рецептивное поле

Область входа, влияющая на один элемент карты признаков. Стек из $L$ слоёв $k\times k$ с шагом 1: $\text{RF} = 1 + L(k - 1)$
(2 слоя $3\times3$ → $5\times5$, 3 → $7\times7$). Каждое понижение разрешения удваивает скорость роста.
**Правило VGG:** вместо $5\times5$ — две $3\times3$: то же поле, на 28% меньше весов и на одну нелинейность больше.
Если сеть «не видит» контекст — посчитайте рецептивное поле: часто оно физически меньше объекта ([формула с шагами](deep.md#4-рецептивное-поле)).

### Свёртка 1×1

Полносвязный слой **по каналам**, одинаковый для всех пикселей (соседей не смотрит); весов $C_{\text{in}}C_{\text{out}}$ — в 9 раз меньше,
чем у $3\times3$. «Смешать пространство и смешать каналы — две разные задачи; $1\times1$ решает вторую, не платя за первую».
Применения: **bottleneck** (сжать каналы → дорогая $3\times3$ → разжать: 69 тыс. весов против 590 тыс.), выравнивание каналов в
skip connection, дешёвая нелинейность (маленький MLP в каждом пикселе), **голова сегментации** ($C$ признаков → $K$ классов в пикселе).

## 3. Pooling

**Агрегация (субдискретизация):** для каждого канала независимо — max или mean в окне (обычно $2\times2$ с шагом 2 → разрешение
вдвое меньше); число каналов сохраняется. Max-pooling — «опросить соседей, есть ли кошка». При дифференцировании градиент
возвращается в позиции максимумов.

Зачем исторически пулинг, а не свёртка с шагом: инвариантность к сдвигу, дополнительная нелинейность, скорость.
**Сегодня это не догма:** в ResNet и далее разрешение понижают **свёрткой с шагом 2**, а пулинг остаётся в конце — **глобальный**.

**Эквивариантность ≠ инвариантность.** Свёртка эквивариантна к сдвигу (сдвинули вход — сдвинулась карта признаков);
инвариантность добавляет пулинг. Путать нельзя ([почему CNN не полностью инвариантна](deep.md#5-эквивариантность-и-инвариантность)).

## 4. Устройство CNN

**Мотивация свёрточного слоя:** разреженные взаимодействия (нейрон видит своё окно), **разделение параметров** (одна свёртка по
всему изображению), **эквивариантность к сдвигу**.

**Схема:** $n\times$[свёртка → (BN) → активация → (пулинг)] + **голова**. По ходу сети разрешение падает, каналов больше:
64 → 128 → 256 → 512. **Иерархия признаков** (ZFNet, Lee et al.): первые слои — края и пятна цвета, затем текстуры и части,
затем объекты.

**Последние слои:** переход от пространства $H\times W$ к вектору признаков:
- **Flatten** сохраняет порядок, но жёстко фиксирует размер входа ($7\times7\times512$ и никак иначе);
- **GAP** (global average pooling) — положение теряется совсем, зато сеть работает с любым разрешением и параметров нет.

Далее «обычные» полносвязные слои (классификация/регрессия). Сети совсем без полносвязных слоёв (**fully convolutional**) нужны
для сегментации (тема 17).

**MNIST:** линейная модель 92.0%, свёрточная 97.5%.

**Dropout и BN в CNN:** `nn.Dropout2d` гасит **каналы** целиком (соседние пиксели скоррелированы); на практике сильнее работает
**аугментация входа** (кропы, отражения, cutout). `nn.BatchNorm2d(C)` — статистики по батчу и всем позициям, по одному числу на
канал, $2C$ параметров; перед BN у свёртки `bias=False`.

```python
class CNN(nn.Module):
    """n × [свёртка → BN → ReLU → пулинг] + голова GAP + Linear (как в семинаре 3)."""
    def __init__(self, n_out=10, w=32):
        super().__init__()
        def block(c_in, c_out):
            return nn.Sequential(nn.Conv2d(c_in, c_out, 3, padding=1, bias=False), nn.BatchNorm2d(c_out),
                                 nn.ReLU(), nn.MaxPool2d(2))
        self.features = nn.Sequential(block(1, w), block(w, 2 * w), block(2 * w, 2 * w))
        self.pool = nn.AdaptiveAvgPool2d(1)
        self.head = nn.Linear(2 * w, n_out)

    def forward(self, x):
        return self.head(self.pool(self.features(x)).flatten(1))
```

## 5. Архитектуры: AlexNet → VGG → Inception → ResNet

ILSVRC (ImageNet: 1.2 млн картинок, 1000 классов): за пять лет ошибка упала в семь раз; все победители после 2012 — CNN.

| Сеть | Год | Идея | Цифры |
|---|---|---|---|
| **AlexNet** | 2012 | ReLU вместо sigmoid/tanh (в разы быстрее), dropout 0.5, аугментации (кропы, отражения), обучение на 2 GPU (→ group convolutions) | top-5: 25.8% → **16.4%** за год |
| **VGG-16** | 2014 | **только $3\times3$** и пулинг $2\times2$; глубина вместо размера ядра; каналы удваиваются после пулинга | 138 млн параметров, из них 103 млн — первый FC |
| **GoogLeNet / Inception** | 2014 | параллельно $1\times1$, $3\times3$, $5\times5$, пулинг — склейка по каналам; **$1\times1$ сжимает каналы** перед дорогими свёртками | 22 слоя, **6.8 млн** параметров — в 20 раз меньше VGG, и точнее |
| **ResNet** | 2015 | **residual-связь** $F(x) + x$: блок учит поправку; градиент идёт в обход блоков | 152 слоя, top-5 **3.57%** < человек 5.1% |
| MobileNet | 2017 | depthwise separable свёртки — в ~9 раз дешевле | для мобильных устройств |

Почему AlexNet сработала именно тогда: появился **ImageNet** (раньше таких данных не было) и **GPU** (свёртка сводится к
перемножению матриц).

**ResNet и проблема деградации:** у 56-слойной сети ошибка выше, чем у 20-слойной, **даже на обучении** — проблема не в переобучении,
оптимизация не справляется. «Ничего не делать» для residual-блока — это обнулить веса $F$ ([почему градиент не затухает](deep.md#8-resnet-почему-градиент-не-затухает)).

```python
class BasicBlock(nn.Module):
    def __init__(self, c):
        super().__init__()
        self.f = nn.Sequential(nn.Conv2d(c, c, 3, padding=1, bias=False), nn.BatchNorm2d(c), nn.ReLU(),
                               nn.Conv2d(c, c, 3, padding=1, bias=False), nn.BatchNorm2d(c))
    def forward(self, x):
        return torch.relu(self.f(x) + x)          # skip connection
```

## 6. Аугментации

Аугментация — способ сказать сети: «**эти преобразования не меняют ответ**». Правильное — качество растёт; неправильное — вы
учите сеть неправде. Это **утверждение о вашей задаче**, а не универсальная кнопка.

Семинар (цифры на холсте $20\times20$, обучение на центрированных, тест со сдвигом):

| Аугментация | MLP центр / сдвиг | CNN центр / сдвиг |
|---|---|---|
| без аугментации | 0.940 / 0.123 | 0.974 / 0.608 |
| + случайный сдвиг | 0.903 / 0.249 | 0.974 / **0.958** |
| + отражение по горизонтали | 0.901 / 0.115 | 0.942 / 0.497 |

1. Сдвиговая аугментация чинит CNN почти полностью (разделение весов доделывает остальное).
2. MLP та же аугментация помогает слабо — нет механизма переноса между положениями; **аугментация не заменяет архитектуру**.
3. **Отражение вредит**: зеркальная двойка — не двойка. Для фото кошек отражение верно, для цифр и дорожных знаков — нет.

```python
from torchvision import transforms as T
train_tf = T.Compose([T.RandomResizedCrop(224, scale=(0.6, 1.0)), T.RandomHorizontalFlip(),
                      T.ColorJitter(0.2, 0.2, 0.2), T.ToTensor(),
                      T.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])])
test_tf = T.Compose([T.Resize(256), T.CenterCrop(224), T.ToTensor(),
                     T.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])])
```

## 7. Transfer learning

**Зачем:** обучить ResNet-50 на ImageNet — дни на нескольких GPU; а в вашей задаче обычно ~2000 картинок и 5 классов — сеть на
25 млн параметров с нуля их просто запомнит. **Ранние слои** выучивают края, пятна цвета, текстуры — они одинаковы у кошек,
клеток крови и спутниковых снимков; **специфика задачи** — в последних блоках и голове. Свою CNN с нуля сегодня почти никогда не учат;
в сегментации и детекции предобученный бэкбон подразумевается.

| Режим | Что обучаем | Когда |
|---|---|---|
| **Feature extraction** | только новую голову, бэкбон заморожен (`requires_grad=False`) | очень мало данных, близкий домен |
| **Fine-tuning** | всю сеть (или последние блоки) с **маленьким темпом** (в 10–100 раз меньше) | данных больше / домен дальше |
| С нуля | всё | много данных или совсем другой домен |

Правила:
- голову заменяем на свою (выходов = число классов);
- разморозили бэкбон — уменьшайте темп: большой шаг разрушит то, ради чего брали веса; **разные темпы** для бэкбона и головы;
- **BatchNorm в замороженном бэкбоне — в `eval`**, иначе running-статистики «поедут» на ваших данных;
- **вход нормировать теми же mean/std, что при предобучении** — `weights.transforms()`; самая частая ошибка.

```python
from torchvision import models
weights = models.ResNet50_Weights.IMAGENET1K_V2
m = models.resnet50(weights=weights)
for p in m.parameters():
    p.requires_grad = False                         # заморозили бэкбон
m.fc = nn.Linear(m.fc.in_features, 5)               # своя голова
preprocess = weights.transforms()                    # тот же препроцессинг, что при предобучении
opt = torch.optim.AdamW([p for p in m.parameters() if p.requires_grad], lr=1e-3)

# fine-tuning с разными темпами
for p in m.layer4.parameters():
    p.requires_grad = True
opt = torch.optim.AdamW([{"params": m.layer4.parameters(), "lr": 1e-4},
                         {"params": m.fc.parameters(), "lr": 1e-3}])
```

**Результаты семинара** (бэкбон обучен на цифрах 0–4, перенос на 5–9 с малым числом примеров):
- при 3–5 примерах на класс **перенос выигрывает** у обучения с нуля;
- **feature extraction рано упирается в потолок** (0.45 → 0.56 при росте выборки в 17 раз) — плато = пора размораживать;
- при ~50 примерах на класс обучение с нуля догоняет и обгоняет;
- правило «маленький η при разморозке» здесь не подтвердилось — домены A и B одинаковые, разрушать нечего;
- **ResNet18 с ImageNet проиграл крошечному бэкбону** с соседней задачи (feature extraction 0.25 против 0.45 при 3 примерах/класс;
  fine-tuning layer4 при 50 примерах 0.67 против 0.90): решает **близость доменов**. «Берём ImageNet-бэкбон» — правило для **фотографий**;
- **ошибки препроцессинга:** пиксели 0…255 вместо нормировки → явная ерунда («вантуз» с уверенностью 1.00); забытые mean/std или
  BGR вместо RGB → правдоподобные ответы с другой уверенностью — ошибку **не видно**.
