# 18. Детекция объектов

[Шпаргалка (ноутбук)](../../cheatsheet.ipynb) · [Оглавление курса](../../README.md)

**Суть.** Ответ — список **переменной длины**: рамка + класс + уверенность для каждого объекта. Двухстадийные детекторы
(R-CNN → Fast → **Faster R-CNN**: RPN предлагает кандидатов, вторая стадия классифицирует) точнее; одностадийные (**YOLO**, RetinaNet)
быстрее: сетка + **якоря** (предсказываем поправку к заготовке) + **NMS**. Дальше — anchor-free (CenterNet, FCOS) и **DETR** (венгерское
сопоставление, без NMS). Качество — **mAP** (по классам и порогам IoU).

| Термин | Определение |
|---|---|
| `xyxy` / `xywh` / `cxcywh` | форматы рамки: углы / угол+размеры (COCO) / центр+размеры (YOLO) |
| Якорь | рамка-заготовка; сеть предсказывает $t_x,t_y,t_w,t_h$ поправки |
| RPN | свёрточная голова «объект/фон + рамка» для $k$ якорей в каждой точке карты |
| RoI Pooling / Align | вырезать кусок карты признаков в фикс. размер; Align — без округлений (билинейно) |
| NMS | оставить самую уверенную рамку, удалить пересекающиеся сильнее порога, повторить |
| AP / mAP@0.5 / mAP@0.5:0.95 | площадь под PR-кривой / среднее по классам при IoU 0.5 / среднее по 10 порогам (COCO) |
| Focal loss | $-\alpha(1-p_t)^\gamma\ln p_t$ — гасит лёгкие фоновые якоря |
| Mask R-CNN | Faster R-CNN + ветка маски $28\times28$ → instance-сегментация |

$$
\text{IoU}=\frac{|A\cap B|}{|A\cup B|},\qquad t_x=\frac{x-x_a}{w_a},\; t_w=\ln\frac{w}{w_a},\qquad
\text{AP}=\sum_k(R_k-R_{k-1})\max_{r\ge R_k}P(r)
$$

<details>
<summary><b>1. Постановка</b></summary>

**Детекция** — найти все объекты: для каждого **рамка, класс и уверенность**. Первая задача курса, где ответ имеет **переменную длину**
(0, 1 или 40 объектов) — отсюда почти все сложности: архитектуры, метрики, необходимость давить дубликаты.

**Где нужна:** беспилотники (машины, пешеходы, знаки), видеонаблюдение и подсчёт, ритейл (товар на полке), медицина (находки на снимке).
Нужен факт, счёт или трекинг, а не форма. Рамку размечают за секунды, маску — за часы → детекция — самая массовая задача CV в продакшене.

**Форматы рамки** (самая частая ошибка — перепутать: код не падает, метрика ≈ 0):

| Формат | Числа | Где |
|---|---|---|
| `xyxy` | углы $(x_1, y_1, x_2, y_2)$ | Pascal VOC, torchvision |
| `xywh` | угол и размеры $(x, y, w, h)$ | COCO |
| `cxcywh` | центр и размеры | YOLO, DETR |

Координаты — в пикселях или нормированные на размер кадра; ось $y$ смотрит **вниз**. Сеть почти никогда не предсказывает координаты
напрямую — только **поправку к заготовке** (якорю).

**Почему нельзя просто регрессировать рамку:** у сети фиксированный выход, а число объектов неизвестно; регрессор, обученный на
кадрах с разными объектами, выдаёт «среднюю» рамку, не совпадающую ни с одним. Все архитектуры — разные ответы на вопрос, **как из
сети с фиксированным выходом получить список переменной длины**.

</details>

<details>
<summary><b>2. Метрики</b></summary>

**IoU на рамках** — площадь пересечения / площадь объединения (та же формула, что на масках). IoU 0.5 — заметно смещённая рамка;
порог 0.5 очень мягкий.

**Сопоставление предсказаний с разметкой** (три правила): предсказания разбираются по убыванию уверенности; верное — если IoU с объектом
≥ порога; **один объект засчитывается один раз** (дубликат — ложное срабатывание).

**PR-кривая и AP:** порог уверенности прогоняют от 1 до 0 (ниже порог → выше полнота, ниже точность); **AP** — площадь под PR-кривой,
одно число для всего компромисса (варианты интерполяции (см. раздел «2. Сопоставление и Average Precision»)).

| Метрика | Определение |
|---|---|
| AP | для одного класса при одном пороге IoU |
| **mAP** | среднее AP по классам (редкий класс = частый) |
| **mAP@0.5** | порог IoU 0.5 — старый стандарт Pascal VOC |
| **mAP@0.5:0.95** | среднее по 10 порогам 0.5…0.95 с шагом 0.05 — «AP» в статьях про COCO; награждает точность границ |
| AP_S, AP_M, AP_L | по мелким, средним, крупным объектам — мелкие всегда хуже |

Важно: 37 mAP на COCO и 76 mAP на VOC могут быть **одной моделью** — разные данные и определения; сравнивать только числа, посчитанные
одним кодом на одних данных. Число предсказаний на кадр ограничивают сотней.

</details>

<details>
<summary><b>3. Двухстадийные детекторы: R-CNN → Fast → Faster</b></summary>

Наивный путь — **перебрать все окна** и классифицировать каждое: окон слишком много, объекты любого размера и формы. История детекции —
как сократить перебор: умным алгоритмом → самой сетью → отказом от перебора.

| | R-CNN (2014) | Fast R-CNN (2015) | Faster R-CNN (2015) |
|---|---|---|---|
| Кандидаты | selective search (~2000, не нейросеть: склейка похожих по цвету/текстуре кусков) | selective search | **RPN** (сама сеть, ~300) |
| Прогонов бэкбона на кадр | ~2000 (каждый кандидат растянут до 227×227) | **1** | 1 |
| Класс и рамка | линейные SVM + отдельная регрессия | две головы сети (softmax + поправки) | две головы |
| Обучение | 3 этапа, признаки на диске (сотни ГБ) | один этап, но кандидаты внешние | всё одной сетью |
| Скорость (VGG-16) | 47 с/кадр | ~2.3 с (сеть 0.32 с, остальное — selective search) | **0.2 с** (5 FPS) |
| mAP VOC 2007 | 66.0 | 66.9 | 69.9 |

- **R-CNN** показал главное: признаки CNN, предобученной на ImageNet, **переносятся в детекцию** (+30% относительно прежнего лучшего на VOC 2012).
- **RoI Pooling** (Fast R-CNN): кусок карты признаков любого размера → $7\times7$ (max в каждой ячейке, по каналам) → вход фиксированной длины
  для полносвязных голов. Бэкбон один раз, RoI Pooling — дёшево, 2000 раз. Обучение 84 → 9.5 часов.
- **RPN** (Faster R-CNN): свёртка $3\times3$ по карте признаков и две головы $1\times1$: **objectness** («объект/фон», 2k чисел) и рамка (4k чисел) для $k$
  якорей в каждой точке; классов нет. ~10 мс вместо ~2 с. «Sliding window» — это просто свёртка. RPN — «детектор одного класса» внутри детектора.
- Первая стадия — «где вообще что-то есть» (без классов), вторая — «что это» + уточнение рамки. Точно, но медленно: вторая стадия на каждого кандидата.

</details>

<details>
<summary><b>4. YOLO: детекция за один проход</b></summary>

**Идея:** убрать первую стадию. Сжать кадр до $448\times448$ → **один** прогон → NMS. **45 FPS** против 5 у Faster R-CNN (впервые реальное время),
но 63.4 mAP против 73.2 (больше всего ошибок в положении рамки, особенно у мелких объектов).

**Сетка $S\times S$ ($7\times7$):** за объект отвечает ячейка, куда попал его центр. В ячейке $B = 2$ рамки по 5 чисел ($x, y$ — центр внутри ячейки,
$w, h$ — доли кадра, уверенность = «есть объект» × IoU) и **один набор** из 20 вероятностей классов. Итоговая оценка рамки — вероятность класса
× уверенность. Выход фиксирован: $7\times7\times30 = 1470$ чисел. Архитектура — обычная CNN (24 свёртки + 2 FC), «детекционное» — только в том,
как читается выход; бэкбон предобучен на ImageNet.
Важно: Слабое место — 2 рамки и 1 класс на ячейку: стая птиц / толпа вдали теряются.

**Функция потерь** — одна сумма квадратов (координаты, уверенность, классы): $\lambda_{\text{coord}} = 5$, $\lambda_{\text{noobj}} = 0.5$ (пустых ячеек большинство),
$\sqrt w, \sqrt h$ (промах в 10 px хуже у мелкой рамки), за координаты штрафуется только «ответственная» рамка — с наибольшим IoU
(формула (см. раздел «4. Функция потерь YOLO v1»)). «Ответственная» рамка — **назначение** (assignment); у каждого детектора своё правило.

**Якоря (YOLOv2, 2017)**

**Якорь** — заданная заранее рамка-заготовка; в каждой ячейке несколько якорей разной формы, для каждого — поправки, уверенность и свои
классы. Центр $b_x = \sigma(t_x) + c_x$ (сигмоида держит центр в ячейке), размер $p\cdot e^{t}$ ($t = 0$ — ровно якорь). YOLOv2: вход 416, сетка $13\times13$,
5 якорей → 845 рамок. mAP почти тот же (69.5 → 69.2), **полнота 81 → 88%** — стоящие рядом объекты перестали теряться.

- **Назначение:** объект достаётся клетке его центра и в ней — якорю самой похожей **формы**; назначенный учится всему, остальные — «объекта нет»
  (но не штрафуются, если и так накрывают объект с IoU > 0.6). В RPN — пороги IoU (> 0.7 объект, < 0.3 фон), в DETR — венгерский алгоритм.
- **Формы якорей — k-means** по $(w, h)$ рамок обучающей выборки с расстоянием $1 - \text{IoU}$; 5 кластеров ≈ 9 ручных якорей.
- Меняется только последний слой; все $k$ предсказаний клетки видят один вектор признаков — разными их делает обучение.

**NMS (non-maximum suppression)**

Соседние ячейки и якоря видят один объект → гроздь почти одинаковых рамок. **Берём самую уверенную, выбрасываем всё, что пересекается
с ней сильнее порога, повторяем.** Порог 0.5–0.7 (ниже — теряются объекты вплотную); по каждому классу отдельно; **soft-NMS** понижает уверенность
вместо удаления. Важно: NMS — постобработка, не часть сети: градиент через неё не идёт, порог обучением не подобрать.

**Семейство YOLO и выбор**

v2 — якоря k-means + BN; **v3** — предсказания с **трёх карт** разного разрешения (мелкие объекты — на детальных картах); дальше версии каждый год,
ядро (сетка, якоря или их замена, NMS) прежнее. YOLO11 (семинар): выход $84\times8400$ = 4 координаты + 80 классов COCO для
$80^2 + 40^2 + 20^2 = 8400$ точек трёх карт (шаги 8, 16, 32); objectness нет — уверенность = максимум по классам.

**Одностадийные** быстрее и проще в развёртывании; **двухстадийные** точнее на мелких и перекрывающихся. Разрыв закрыли мультимасштабные
предсказания и focal loss. Правило: начинайте с одностадийного. Важно: У YOLO разных версий разные лицензии (вплоть до запрета коммерческого
использования без покупки).

</details>

<details>
<summary><b>5. Focal loss, anchor-free, DETR</b></summary>

**Focal loss** (RetinaNet, 2017): у одностадийного детектора нет первой стадии, отсеивающей фон — десятки тысяч якорей, почти все пустые.
$\text{FL} = -\alpha(1 - p_t)^\gamma\ln p_t$ не выбрасывает лёгкие примеры, а плавно гасит их вклад (подробно (см. раздел «5. Focal loss»)).

**Anchor-free.** Якоря плохи: размеры и соотношения — гиперпараметры под датасет; десятки тысяч якорей, почти все отрицательные; пороги
назначения (0.3/0.7) — тоже гиперпараметры.
- **CenterNet** (Objects as Points, 2019): карта вероятностей центров (своя на класс) + размеры рамки в той же точке; центр — точка больше всех
  8 соседей (max-pooling $3\times3$) → один пик на объект, **NMS не нужен**;
- **FCOS** (2019): каждая точка внутри объекта предсказывает 4 расстояния до сторон рамки.

**DETR** (2020): CNN-бэкбон → трансформер смотрит на всю карту → **100 обучаемых запросов** → 100 предсказаний (класс + рамка или «объекта нет»).
Перед подсчётом потерь — **венгерский алгоритм**: соответствие «предсказание ↔ объект» минимальной суммарной стоимости; без пары —
учится «объекта нет». Дубликатов нет в принципе → **ни якорей, ни NMS**. Цена — 500 эпох на COCO вместо 12 (Deformable DETR, DINO чинят).

**Линия развития:** за пять лет из пайплайна ушли внешний генератор кандидатов, потом якоря, потом NMS — осталась одна сеть, обучаемая целиком.

</details>

<details>
<summary><b>6. Instance-сегментация: Mask R-CNN</b></summary>

**Instance** — каждый объект отдельно и маской (семантическая сегментация не считает объекты, детекция даёт только рамку). Победил путь
**сверху вниз**: найти, потом обвести.

**Mask R-CNN** (2017) = Faster R-CNN + третья ветка: маленькая FCN предсказывает маску $28\times28$ внутри каждого кандидата, **для каждого класса своя**,
выбирается та, что назвала классификационная голова (маски не конкурируют между классами — бинарная сигмоида вместо softmax).
**RoI Align** вместо RoI Pooling: RoI Pooling округляет дважды (рамку до клеток и ячейки до клеток; клетка = 16 пикселей) — маска съезжает;
RoI Align ничего не округляет, берёт 4 точки в ячейке билинейной интерполяцией. Качество масок +10–50% относительно.

**Мелкие объекты решает разрешение входа:** объект 10 пикселей у бэкбона с шагом 16 не попадает даже в одну клетку. Если объект меньше
20 пикселей — увеличивайте разрешение входа, а не глубину сети.

</details>

<summary><b>7. Практика: ultralytics (семинар 5)</b></summary>

```python
from ultralytics import YOLO

model = YOLO("yolo11n.pt")                                   # предобученная на COCO
res = model("street.jpg", conf=0.25, iou=0.7)[0]             # conf — порог уверенности, iou — порог NMS
res.boxes.xyxy, res.boxes.conf, res.boxes.cls                 # рамки, уверенности, классы
# сегментация: res.masks (.data — растр, .xy — полигоны); поза: res.keypoints

model.train(data="carparts.yaml", epochs=40, imgsz=640, fliplr=0.0)   # дообучение на своих данных
metrics = model.val()                                        # metrics.box.map50, metrics.box.map
model.export(format="onnx")                                  # деплой: onnxruntime без PyTorch
```

**Формат разметки YOLO:** на картинку — txt, на объект строка `class cx cy w h` (нормированные); для сегментации — `class x1 y1 x2 y2 ...` (полигон).

**Уроки семинара** (детали машин, 23 класса, 439 train / 146 val кадров, YOLO11n, 40 эпох):
- **Утечка в датасете из интернета:** в исходном carparts-seg 3833 кадра — лишь 585 уникальных фото; из 295 фото валидации **290 были в трейне**
  в аугментированных копиях. Пересобрали: одна копия на фото, сплит по исходникам. Проверяйте дубликаты по разные стороны сплита!
- **Аугментация `fliplr=0.5` по умолчанию** превращала левую дверь/фару в правую с меткой «левая»: mAP50 0.547 → **0.675** с `fliplr=0`
  (классы left/right: 0.439 → 0.736). Аугментация — утверждение о задаче.
- Разброс между сидами ~3 пункта mAP — меньшие различия на одном прогоне ничего не доказывают.
- **С нуля** (`yolo11n.yaml`): mAP50 **0.08** — предобучение решает всё; **заморозка бэкбона** (`freeze=10`): −15 пунктов (признаки COCO про «машину
  целиком»); 80 эпох вместо 40: 0.72 → 0.77.
- Порог NMS: плато 0.3–0.8, выше 0.9 mAP падает. Instance-сегментация: рамки mAP50-95 0.524, маски 0.500 (маской труднее попасть пиксель в пиксель).
- **SAM2** по рамкам детектора: медианный IoU с ручной маской ~0.86, но есть хвост провалов (плоские детали без контрастной границы) —
  отличный **черновик** разметки; `auto_annotate` — детектор → SAM → полигоны YOLO.
- **ONNX:** выход $(1, 27, 8400)$ = 4 + 23 класса; onnxruntime + свой NMS совпадает с ultralytics до долей пикселя; на CPU 57 мс против 92 мс у
  PyTorch; главное — зависимости (onnxruntime + numpy вместо PyTorch). Можно вшить NMS (`nms=True`), half/int8, TensorRT, OpenVINO, CoreML.

```python
import torch, torchvision
def nms(boxes, scores, iou_thr=0.5):                       # boxes: [N, 4] xyxy
    order = scores.argsort(descending=True); keep = []
    while order.numel():
        i = order[0]; keep.append(i.item())
        if order.numel() == 1: break
        iou = torchvision.ops.box_iou(boxes[i:i + 1], boxes[order[1:]])[0]
        order = order[1:][iou <= iou_thr]
    return torch.tensor(keep)
# для нескольких классов: torchvision.ops.batched_nms(boxes, scores, classes, iou_thr)
```

**Рабочий порядок:** COCO (80 классов, ~118 тыс. кадров, ~7 объектов на кадр) — источник почти всех весов; берём готовую реализацию и
веса; свои классы — замена головы и дообучение; аугментации (отражения, кропы, масштаб, **мозаика**) — **рамки преобразуются вместе с
картинкой**; меряем mAP на валидации. **Грабли:** формат рамок; аугментация без рамок; порог NMS по умолчанию на плотной сцене; мелкие объекты;
«обведено не всё» в разметке (пропущенный объект учит сеть считать его фоном). Порядок улучшений: данные и разметка → разрешение и
аугментации → пороги → архитектура.

**Главная мысль лекции:** детекция — это борьба с переменным числом ответов, и почти каждая новая идея убирает из пайплайна ещё одну
необучаемую деталь.

**Математика и выводы**

<details>
<summary><b>1. IoU рамок и его обобщения</b></summary>

Рамки $A = (x_1, y_1, x_2, y_2)$, $B = (x_1', y_1', x_2', y_2')$. Пересечение:

$$
w_\cap = \max\big(0, \min(x_2, x_2') - \max(x_1, x_1')\big),\quad h_\cap = \max\big(0, \min(y_2, y_2') - \max(y_1, y_1')\big),
$$

$$
\text{IoU} = \frac{w_\cap h_\cap}{|A| + |B| - w_\cap h_\cap} .
$$

Интуиция порога: две рамки одного размера, сдвинутые на треть ширины по одной оси, дают $\text{IoU} = \frac{2/3}{4/3} = 0.5$ — «заметно смещённая
рамка», порог 0.5 мягкий.

**Как loss IoU плох:** при непересекающихся рамках $\text{IoU} = 0$ и градиент нулевой. Обобщения:
- **GIoU** $= \text{IoU} - \frac{|C\setminus(A\cup B)|}{|C|}$, $C$ — минимальная охватывающая рамка: даже без пересечения тянет рамки друг к другу;
- **DIoU** $= \text{IoU} - \frac{\rho^2(c_A, c_B)}{d_C^2}$ — штраф за расстояние центров ($d_C$ — диагональ $C$);
- **CIoU** — DIoU + штраф за разницу соотношений сторон. Используются как loss регрессии рамок (YOLO v4+, DETR — GIoU).

</details>

<details>
<summary><b>2. Сопоставление и Average Precision</b></summary>

Для одного класса и порога IoU $\tau$:
1. предсказания сортируются по убыванию уверенности;
2. предсказание — **TP**, если IoU с ещё не занятым объектом той же картинки $\ge \tau$ (берём объект с максимальным IoU); иначе **FP**;
3. каждый объект засчитывается **один раз** — дубликат того же объекта — FP (поэтому без NMS precision падает).

Идя по списку, получаем точки $(R_k, P_k)$: $P_k = \frac{TP_k}{k}$, $R_k = \frac{TP_k}{N_{\text{gt}}}$. **AP** — площадь под PR-кривой, сделанной монотонной
(интерполированной): $P_{\text{interp}}(r) = \max_{r' \ge r}P(r')$.

$$
\text{AP}_{\text{all-point}} = \sum_k (R_k - R_{k-1})\,P_{\text{interp}}(R_k), \qquad
\text{AP}_{\text{VOC07}} = \frac{1}{11}\sum_{r\in\lbrace0, 0.1, \dots, 1\rbrace}P_{\text{interp}}(r), \qquad
\text{AP}_{\text{COCO}}: 101 \text{ точка } r\in\lbrace0, 0.01, \dots, 1\rbrace .
$$

**mAP** — среднее AP по классам (редкий класс весит как частый). **mAP@0.5** — VOC; **mAP@0.5:0.95** (COCO «AP») — среднее по 10 порогам
$\tau = 0.5, 0.55, \dots, 0.95$: награждает точность границ. COCO также: AP_S/M/L (объекты < $32^2$, $32^2$–$96^2$, > $96^2$ пикселей), не более 100
предсказаний на кадр (иначе полноту накручивают мусором). Падение mAP@0.5:0.95 при росте mAP@0.5 означает: находим больше объектов,
но рамки стали менее точными.

**Без NMS:** две рамки на одном объекте с уверенностью 0.9 и 0.8 — первая TP, вторая FP; precision на этом уровне recall падает.

</details>

<details>
<summary><b>3. Параметризация рамок относительно якоря</b></summary>

**Faster R-CNN / RPN.** Якорь $(x_a, y_a, w_a, h_a)$ (центр, размеры), рамка $(x, y, w, h)$. Цели регрессии:

$$
t_x = \frac{x - x_a}{w_a},\quad t_y = \frac{y - y_a}{h_a},\quad t_w = \ln\frac{w}{w_a},\quad t_h = \ln\frac{h}{h_a} .
$$

Нормировка на размер якоря делает цели масштабно-инвариантными; логарифм — положительность размеров и симметрию «в 2 раза
больше/меньше». Loss — **smooth L1** (Huber с $\delta = 1$, тема [01](../01_intro_regression_metrics/README.md)), только по положительным якорям:
у фона нет «правильной» рамки, регрессировать не к чему.

**RPN:** якорь положительный при IoU > 0.7 с каким-либо объектом (или максимальный IoU для объекта), отрицательный при IoU < 0.3, остальные
не участвуют; в батче 256 якорей с долей положительных до 1:1. Классический набор: 3 масштаба × 3 соотношения = 9 якорей на точку.

**YOLOv2:** $b_x = \sigma(t_x) + c_x$, $b_y = \sigma(t_y) + c_y$ (центр не может уйти из ячейки $(c_x, c_y)$ — стабильность в начале обучения),
$b_w = p_we^{t_w}$, $b_h = p_he^{t_h}$ ($t = 0$ — ровно якорь $p$).

**Якоря k-means с расстоянием $1 - \text{IoU}$:** кластеризуем только $(w, h)$ (рамки совмещены центрами). С евклидовым расстоянием крупные
рамки давали бы большие расстояния и перевешивали; $1 - \text{IoU}$ масштабно-инвариантно. 5 кластеров дают средний IoU 61.0 — как 9
ручных якорей (60.9).

</details>

<details>
<summary><b>4. Функция потерь YOLO v1</b></summary>

Сетка $S\times S$, в ячейке $B$ рамок и $C$ вероятностей классов; $\mathbb{1}_{ij}^{\text{obj}}$ — рамка $j$ ячейки $i$ «ответственна» за объект
(максимальный IoU с правдой среди рамок ячейки):

$$
\begin{aligned}
L ={}& \lambda_{\text{coord}}\sum_{i,j}\mathbb{1}_{ij}^{\text{obj}}\Big[(x_i - \hat x_i)^2 + (y_i - \hat y_i)^2\Big]
 + \lambda_{\text{coord}}\sum_{i,j}\mathbb{1}_{ij}^{\text{obj}}\Big[(\sqrt{w_i} - \sqrt{\hat w_i})^2 + (\sqrt{h_i} - \sqrt{\hat h_i})^2\Big]\\
&+ \sum_{i,j}\mathbb{1}_{ij}^{\text{obj}}(C_i - \hat C_i)^2 + \lambda_{\text{noobj}}\sum_{i,j}\mathbb{1}_{ij}^{\text{noobj}}(C_i - \hat C_i)^2
 + \sum_i\mathbb{1}_i^{\text{obj}}\sum_{c}\big(p_i(c) - \hat p_i(c)\big)^2 ,
\end{aligned}
$$

$\lambda_{\text{coord}} = 5$, $\lambda_{\text{noobj}} = 0.5$. **Почему $\sqrt w$:** $\frac{d\sqrt w}{dw} = \frac{1}{2\sqrt w}$ — ошибка в 10 пикселей у узкой рамки весит больше, чем у широкой
(относительная точность). **Почему $\lambda_{\text{noobj}}$:** пустых ячеек большинство, без понижения их «объекта нет» задавило бы градиент — ручная
борьба с дисбалансом, которую позже системно решил focal loss. Целевая уверенность $C_i$ = IoU предсказанной рамки с правдой.
Выход: $7\times7\times(2\cdot5 + 20) = 1470$ чисел.

</details>

<details>
<summary><b>5. Focal loss</b></summary>

Одностадийный детектор оценивает десятки тысяч якорей (RetinaNet ~100k), из них положительных единицы. Даже если каждый лёгкий
отрицательный пример даёт маленький CE (при $p_t = 0.9$ это 0.105), их сумма доминирует. **Focal loss** (Lin et al., 2017):

$$
\text{FL}(p_t) = -\alpha_t(1 - p_t)^\gamma\ln p_t,\qquad p_t = \begin{cases}p, & y = 1\\ 1 - p, & y = 0\end{cases} .
$$

При $\gamma = 2$: пример с $p_t = 0.9$ теряет вес в 100 раз, с $p_t = 0.99$ — в $10^4$ раз; трудные примеры ($p_t$ мало) почти не меняются. Лёгкие
примеры не выбрасываются, а плавно гасятся. $\alpha \approx 0.25$ для положительных (баланс в паре с $\gamma$). Инициализация смещения последнего
слоя $b = -\ln\frac{1-\pi}{\pi}$ ($\pi = 0.01$) — чтобы на старте все якоря предсказывали «фон» с вероятностью 0.99 и loss не взрывался.
RetinaNet (одностадийный + FPN + focal loss) догнал двухстадийные по точности.

</details>

<details>
<summary><b>6. NMS и soft-NMS</b></summary>

**Greedy NMS:** пока кандидаты есть — взять максимальный по уверенности, добавить в ответ, удалить все с IoU > порога. Сложность $O(n^2)$ в
худшем случае. Делается **по классам** (трюк: сдвинуть рамки каждого класса на большое смещение $c\cdot M$ — рамки разных классов
перестают пересекаться, хватает одного прохода: `torchvision.ops.batched_nms`).

**Soft-NMS** (Bodla et al., 2017): вместо удаления понижает уверенность пересекающихся рамок:
$s_i \leftarrow s_i\cdot e^{-\text{IoU}(M, b_i)^2/\sigma}$ (гауссов вариант) — спасает объекты, стоящие вплотную.

Семинар: зависимость mAP от порога IoU NMS — плато от 0.3 до 0.8 (меняется меньше пункта; дефолт ultralytics 0.7); выше 0.9 mAP падает,
при 0.99 — почти вдвое (дубли = ложные срабатывания).

</details>

<details>
<summary><b>7. RoI Pooling и RoI Align</b></summary>

RoI Pooling: проекция рамки на карту признаков (шаг бэкбона, например 16) **с округлением** до клеток, деление на сетку $7\times7$ **с
округлением**, max в каждой ячейке. Две квантизации дают сдвиг до половины клетки ≈ 8 пикселей кадра — для класса неважно, для маски
$28\times28$ — заметно.

**RoI Align** (Mask R-CNN): без округлений; в каждой из $7\times7$ ячеек берутся 4 регулярно расположенные точки с **вещественными**
координатами, значение признаков в них — **билинейной интерполяцией** по четырём соседним клеткам карты, затем max/average. Градиент
дифференцируем по признакам. Улучшение масок на 10–50% относительно.

</details>

<details>
<summary><b>8. Anchor-free и DETR</b></summary>

**CenterNet** (Objects as Points): тепловая карта центров $\hat Y \in [0,1]^{\frac{W}{R}\times\frac{H}{R}\times C}$; целевая карта — гауссианы
$\exp\big(-\frac{(x - \tilde p_x)^2 + (y - \tilde p_y)^2}{2\sigma_p^2}\big)$ вокруг центров объектов ($\sigma_p$ зависит от размера объекта), loss — вариант focal loss с
понижением штрафа вблизи центра. В пике дополнительно предсказываются размеры и смещение (компенсация дискретизации). Центр —
локальный максимум (max-pooling $3\times3$) → один пик на объект, NMS не нужен.

**FCOS:** каждая точка внутри объекта регрессирует расстояния до сторон $(l, t, r, b)$; **centerness**
$\sqrt{\frac{\min(l, r)}{\max(l, r)}\cdot\frac{\min(t, b)}{\max(t, b)}}$ подавляет рамки от точек у края объекта; уровни FPN разделяют объекты по размеру.

**DETR:** $N = 100$ обучаемых запросов → $N$ предсказаний (класс или «∅», рамка). **Венгерский алгоритм** находит перестановку $\hat\sigma$,
минимизирующую сумму стоимостей:

$$
\hat\sigma = \arg\min_\sigma\sum_{i}\Big[-\mathbb{1}_{c_i\ne\varnothing}\,\hat p_{\sigma(i)}(c_i) + \mathbb{1}_{c_i\ne\varnothing}\big(\lambda_{L1}\|b_i - \hat b_{\sigma(i)}\|_1 + \lambda_{\text{GIoU}}(1 - \text{GIoU}(b_i, \hat b_{\sigma(i)}))\big)\Big],
$$

затем loss — кросс-энтропия по классам (включая ∅ для несопоставленных) + L1 + GIoU по сопоставленным парам. Объект «занят» ровно
одним предсказанием → дубликатов нет, NMS не нужен. Цена — медленная сходимость (500 эпох COCO против 12); Deformable DETR, DINO
исправляют. YOLO26 в семинаре тоже умеет работать без NMS (на 40 эпохах 0.40 против 0.53 mAP50 с NMS).

</details>

<summary><b>Примеры кода (с результатами запуска)</b></summary>

Запустить их можно в ноутбуке [`cheatsheet.ipynb`](../../cheatsheet.ipynb).

```python
import torch, torchvision
torch.manual_seed(0)

def box_iou(a, b):                                   # a: [N,4], b: [M,4] в xyxy
    lt = torch.max(a[:, None, :2], b[None, :, :2]); rb = torch.min(a[:, None, 2:], b[None, :, 2:])
    inter = (rb - lt).clamp(min=0).prod(-1)
    area = lambda x: (x[:, 2] - x[:, 0]) * (x[:, 3] - x[:, 1])
    return inter / (area(a)[:, None] + area(b)[None, :] - inter)

def nms(boxes, scores, thr=0.5):
    order, keep = scores.argsort(descending=True), []
    while order.numel():
        i = order[0]; keep.append(int(i))
        order = order[1:][box_iou(boxes[i:i + 1], boxes[order[1:]])[0] <= thr]
    return torch.tensor(keep)

print("IoU сдвига на 1/3 ширины:", box_iou(torch.tensor([[0., 0., 3., 3.]]), torch.tensor([[1., 0., 4., 3.]])).item())
gt = torch.tensor([[10., 10., 50., 60.], [70., 20., 120., 80.]])
boxes = torch.cat([g + torch.randn(15, 4) * 3 for g in gt])            # гроздь рамок на каждом объекте
scores = torch.rand(30)
keep = nms(boxes, scores, 0.5)
print(f"кандидатов {len(boxes)} → после NMS {len(keep)}; совпадает с torchvision:",
      sorted(keep.tolist()) == sorted(torchvision.ops.nms(boxes, scores, 0.5).tolist()))
```

Результат запуска:

```text
IoU сдвига на 1/3 ширины: 0.5
кандидатов 30 → после NMS 2; совпадает с torchvision: True
```

```python
# AP с нуля: сопоставление по убыванию уверенности, каждый объект засчитывается один раз
def average_precision(pred_boxes, pred_scores, gt_boxes, iou_thr=0.5):
    order = pred_scores.argsort(descending=True); taken = torch.zeros(len(gt_boxes), dtype=torch.bool); tp = []
    for i in order:
        ious = box_iou(pred_boxes[i:i + 1], gt_boxes)[0]; ious[taken] = 0
        j = int(ious.argmax())
        if ious[j] >= iou_thr: taken[j] = True; tp.append(1)
        else: tp.append(0)
    tp = torch.tensor(tp, dtype=torch.float); ctp = tp.cumsum(0)
    prec, rec = ctp / torch.arange(1, len(tp) + 1), ctp / len(gt_boxes)
    prec = torch.flip(torch.cummax(torch.flip(prec, [0]), 0).values, [0])   # монотонная огибающая
    return float(((rec - torch.cat([torch.zeros(1), rec[:-1]])) * prec).sum())

print(f"AP без NMS:  {average_precision(boxes, scores, gt):.3f}  (дубликаты = ложные срабатывания)")
print(f"AP после NMS: {average_precision(boxes[keep], scores[keep], gt):.3f}")
print(f"AP@0.5:0.95 после NMS: {sum(average_precision(boxes[keep], scores[keep], gt, t) for t in torch.arange(0.5, 0.96, 0.05).tolist()) / 10:.3f}")
```

Результат запуска:

```text
AP без NMS:  0.700  (дубликаты = ложные срабатывания)
AP после NMS: 1.000
AP@0.5:0.95 после NMS: 0.650
```
