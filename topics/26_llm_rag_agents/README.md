## Часть A. Промптинг

### 1. Base и instruct — снова

Семинар 11 начинается с того же опыта, что и семинар 10: SmolLM2-135M **base** на вопрос о назначении списка `C` в функции биномиального
коэффициента «продолжает текст» и галлюцинирует (уходит во флуд про факториалы) — она не решает задачу, а продолжает текст наиболее
вероятным образом. **Instruct** с chat template понимает формат «вопрос → ответ», верно описывает конец работы функции, но в деталях
ошибается: маленькая модель понимает задачу лучше, чем знает ответ.

То же различие есть у эмбеддеров: старые (E5 v2) требуют жёстких префиксов `query:` / `passage:`, новые instruction-эмбеддеры принимают
описание задачи текстом («найди ответ на вопрос», «найди дубликат», «найди код»).

### 2. Анатомия промпта

1. **Роль и цель** (system): кто модель и что важно («ты аккуратный ассистент по коду; приоритет — корректность»).
2. **Задача**: что сделать, конкретно и однозначно.
3. **Контекст**: данные, документы (в RAG — найденные фрагменты), разделённые явными границами (`<context>…</context>`, `---`).
4. **Формат ответа**: структура, длина, язык, JSON-схема.
5. **Ограничения**: «если ответа нет в контексте — скажи, что не знаешь», «не придумывай ссылки».
6. **Примеры** (few-shot): несколько пар «вход → выход» — модель копирует формат и стиль.

| Техника | Идея | Когда |
|---|---|---|
| Zero-shot | только инструкция | простые задачи, сильные модели |
| Few-shot / in-context learning | примеры в промпте; важны порядок, баланс меток, формат | классификация, извлечение, нестандартный формат |
| Chain-of-Thought | «рассуждай по шагам», примеры с рассуждениями | арифметика, логика, многошаговые задачи |
| Self-consistency | несколько CoT с сэмплированием → голосование ответов | когда важна точность и есть бюджет |
| ReAct | чередование рассуждения и действий-инструментов | агенты, поиск |
| Структурированный вывод | JSON-схема, constrained decoding (грамматика ограничивает токены) | интеграция с кодом |
| Декомпозиция / цепочки | разбить задачу на шаги-промпты | сложные пайплайны |

Современные «рассуждающие» модели обучены думать перед ответом (RL на проверяемых задачах, [тема 25](../25_llm_finetuning_peft/README.md#11-dpo-и-другие-методы-без-rl)),
и явный CoT для них менее нужен.

### 3. Ограничения LLM, которые промпт не исправит

- **Галлюцинации** — уверенно выдуманные факты и ссылки (L1: «LoRA (Low-Rank Additive Noise Autoencoder)» у модели 1.5B без контекста).
- **Срез знаний** — модель не знает событий после обучения и ваших внутренних документов.
- **Контекст конечен** и дорог; информация в середине длинного контекста используется хуже («lost in the middle»).
- **Арифметика и точные операции** — лучше через инструменты (калькулятор, код).
- **Prompt injection** — инструкции внутри документов, писем, веб-страниц могут «перехватить» модель.

Ответы на первые два ограничения — RAG и инструменты.

## Часть B. Retrieval-Augmented Generation

### 4. Пайплайн

`query → (переписать запрос) → retrieval → (реранкинг) → контекст в промпт → generation → (проверка, цитаты)`

**Индексация (офлайн):** документы → очистка → **чанкинг** → эмбеддинги → векторная база (+ лексический индекс, метаданные).
**Запрос (онлайн):** эмбеддинг запроса → поиск ближайших чанков → промпт «используй контекст» → ответ со ссылками на источники.

Плюсы: актуальные и приватные знания без дообучения; проверяемость (цитаты); меньше галлюцинаций; обновление базы — просто
переиндексация. Минусы: качество ограничено поиском; длинный контекст дороже; модель может проигнорировать или неверно пересказать контекст.

### 5. Чанкинг

- По структуре документа (заголовки, абзацы, функции кода) лучше, чем по фиксированному числу символов.
- Размер: 200–1000 токенов; маленькие — точный поиск, но мало контекста; большие — наоборот. Перекрытие 10–20%.
- `RecursiveCharacterTextSplitter` (семинар: `chunk_size=100`, `chunk_overlap=20` → 7 документов дали 12 чанков) режет по `\n\n`, `\n`, пробелам.
- Приёмы: заголовок документа/раздела в каждом чанке; «маленький чанк для поиска — большой для контекста» (parent document); метаданные (дата, источник) для фильтров.

### 6. Поиск: лексический, плотный, гибрид

| Метод | Как | Сильные стороны | Слабые |
|---|---|---|---|
| **BM25** | TF с насыщением × IDF × нормировка длины ([deep §1](deep.md#1-bm25-из-tf-idf)) | редкие термины, коды, имена; без обучения | синонимы, перефразы |
| **Плотный (bi-encoder)** | $\cos(E(q), E(d))$, ANN-индекс (HNSW, [тема 19](../19_contrastive_embeddings/README.md)) | смысл, перефразы, мультиязычность | редкие термины; зависит от эмбеддера |
| **Гибрид** | RRF или взвешенная сумма нормированных скоров | лучшее из двух | — |
| **Реранкер (cross-encoder)** | пара (запрос, чанк) целиком через BERT → скор; на топ-50 | точность | дорого, только для короткого списка |
| **MMR** | $\arg\max_d\big[\lambda\,\mathrm{sim}(q, d) - (1-\lambda)\max_{d'\in S}\mathrm{sim}(d, d')\big]$ | разнообразие, без дубликатов | — |

L1-пример (494 чанка из конспектов всех 27 тем шпаргалки, 18 вопросов, hit@3): BM25 — 0.94, плотный `multilingual-e5-small` — 1.00, гибрид — 1.00. При
подборе эмбеддера разница бывает огромной: при подготовке примера `rubert-tiny2` с mean-пулингом дал лишь ≈0.2 на тех же вопросах —
модель, не обученная для поиска, плохо ищет.

Эмбеддеры: `multilingual-e5` (префиксы!), `bge-m3`, `paraphrase-multilingual-MiniLM-L12-v2` (семинар), специализированные для русского (по
бенчмарку ruMTEB / MTEB). Векторные базы: FAISS, Chroma (семинар), Qdrant, Milvus, pgvector.

**Улучшения запроса:** переписывание (LLM формулирует поисковый запрос из диалога), multi-query, **HyDE** (сгенерировать гипотетический
ответ и искать по нему), декомпозиция сложного вопроса.

### 7. Генерация с контекстом

```python
system = ("Отвечай кратко и только по контексту. Если в контексте нет ответа — скажи, что не знаешь. "
          "После каждого утверждения укажи номер источника [n].")
user = f"Контекст:\n{numbered_chunks}\n\nВопрос: {question}"
answer = chat([{"role": "system", "content": system}, {"role": "user", "content": user}])
```

L1-пример (Qwen2.5-1.5B-Instruct): без контекста модель расшифровывает LoRA как «Low-Rank Additive Noise Autoencoder» и придумывает
причины; с найденными фрагментами конспекта отвечает по существу: «чтобы модель не была испорчена… градиенты по B ненулевые».

### 8. Семинар 11: RAG на LangChain

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.embeddings import HuggingFaceEmbeddings        # новый пакет: langchain_huggingface
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_classic.chains import create_retrieval_chain
from langchain_classic.chains.combine_documents import create_stuff_documents_chain

texts = RecursiveCharacterTextSplitter(chunk_size=100, chunk_overlap=20).create_documents(documents)
emb = HuggingFaceEmbeddings(model_name="sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2")
vectorstore = Chroma.from_documents(texts, embedding=emb, persist_directory="./chroma_db")
retriever = vectorstore.as_retriever(search_type="similarity", search_kwargs={"k": 3})
# варианты: search_type="similarity_score_threshold" (score_threshold=0.7), "mmr" (k=5, fetch_k=10)
prompt = ChatPromptTemplate.from_messages([("system", "Используй контекст… Контекст: {context}"), ("human", "{input}")])
qa_chain = create_retrieval_chain(retriever, create_stuff_documents_chain(llm, prompt))
result = qa_chain.invoke({"input": "Что такое машинное обучение?"})   # result["answer"], result["context"]
```

Что видно в семинаре и чему стоит научиться на этом:
- С **GPT-2** (не instruct, почти без русского) ответ — бессмыслица на английском: RAG не спасает слабый генератор.
- С **Qwen2.5-0.5B-Instruct** ответ по контексту, но модель повторяет промпт и начинает «редактировать» ответ: `HuggingFacePipeline` + `ChatPromptTemplate`
  склеивают роли в текст «System: … Human: …», а **не** применяют chat template модели, и по умолчанию возвращают промпт вместе с ответом
  (`return_full_text=True`). Для локальных моделей используйте `ChatHuggingFace` / `apply_chat_template` и `return_full_text=False`.
- В LangChain много устаревающих модулей и несовместимостей версий — для простых пайплайнов часто проще 30 строк своего кода (как в L1).
- Задания семинара: добавить реранкер; несколько ролей через разные system prompts; простой агент «найди документы → суммаризируй».

### 9. Оценка RAG

Оценивать **по частям**, иначе непонятно, что чинить:

| Что | Метрики |
|---|---|
| Поиск | recall@k / hit@k, MRR, nDCG по размеченным парам «вопрос → нужный чанк» |
| Верность контексту | **faithfulness**: каждое утверждение ответа подтверждается контекстом |
| Полезность | answer relevance, correctness против эталона |
| Конец-в-конец | доля решённых задач, оценка людьми; LLM-as-a-judge с чёткой рубрикой (проверять согласие с людьми, учитывать склонность судьи к длинным ответам и к своему стилю) |

Фреймворки: RAGAS, DeepEval, TruLens. Набор вопросов собирают из реальных логов + синтетически (LLM генерирует вопросы по чанкам).

## Часть C. Агенты

### 10. Определения

**Агент** — LLM, **автономно использующая инструменты в замкнутом цикле**: модель решает, что делать, обвязка исполняет и возвращает
результат, и так до готовности. «Модель и есть агент»; разработка агентов — это либо обучение модели, либо построение обвязки
(**harness**):

$$
\text{Harness} = \text{Tools} + \text{Knowledge} + \text{Observation} + \text{Action} + \text{Permissions}
$$

- **Tools:** файлы, shell, сеть, база данных, браузер.
- **Knowledge:** документация продукта, справочники, спецификации API, стайлгайды.
- **Observation:** git diff, логи ошибок, состояние браузера, сенсоры.
- **Action:** команды CLI, вызовы API, действия в интерфейсе.
- **Permissions:** песочница, подтверждения опасных действий, границы доверия.

### 11. Tool calling и агентный цикл

Инструмент описывается **именем, описанием и JSON-схемой аргументов**; модель, обученная на вызовах функций, вместо текста выдаёт
структурированный вызов. Цикл:

```python
def agent_loop(messages, tools, handlers, max_turns=20):
    for _ in range(max_turns):
        reply = llm(messages, tools=tools)                  # ответ модели: текст и/или вызовы инструментов
        messages.append({"role": "assistant", "content": reply.content, "tool_calls": reply.tool_calls})
        if not reply.tool_calls:                            # единственный управляющий сигнал: вызовов нет — готово
            return reply.content
        for call in reply.tool_calls:
            result = handlers[call.name](**call.arguments)  # dispatch map: имя → функция
            messages.append({"role": "tool", "tool_call_id": call.id, "content": str(result)})
```

Один проход цикла — **turn** (внутри может быть много вызовов), вся сессия — **thread** (накопленная история). Цикл не меняется —
добавляются механизмы вокруг него. Добавить инструмент = добавить один обработчик в таблицу.

**L1-пример (Qwen2.5-1.5B, инструменты `calculator` и `search_notes`):** на «сколько параметров при 12·d², d = 768» модель вызывает
`calculator("12*768^2")` и получает **9218** — в Python `^` это XOR. Исправление — в **инструменте** (принимать `^` как степень, описать это
в docstring), после чего результат 7 077 888… но модель пересказывает его как «70 778 880». Мораль: обвязка должна валидировать входы
инструментов, а важные значения брать из результатов инструментов, а не из пересказа модели.

### 12. Эволюция обвязки (лекция «Архитектура AI-агентов», А. Мамаев)

Пошаговое построение по учебному репозиторию shareAI-lab (12 шагов; на каждом добавляется **один** механизм, `agent_loop` не меняется):

| Фаза | Шаг | Механизм | Проблема, которую решает |
|---|---|---|---|
| 1. Цикл | s01 | цикл + один инструмент `bash` (< 30 строк) | модель умеет рассуждать, но не действовать |
| | s02 | таблица инструментов (`read_file`, `write_file`, `edit_file`), `safe_path` | всё через shell — непредсказуемо и небезопасно |
| 2. План и знания | s03 | TodoManager: pending / in_progress / completed, одна задача «в работе»; напоминание, если 3 хода без обновления | агент теряет нить на длинных задачах |
| | s04 | субагенты с **чистым** контекстом (`messages=[]`), родителю — только итог | контекст засоряется промежуточным шумом |
| | s05 | **skills**: в system prompt только имена и описания (~100 токенов), тело (~2000) — по запросу `load_skill` | 10 навыков × 2000 токенов в каждом промпте |
| | s06 | сжатие контекста в 3 уровня: старые результаты → плейсхолдеры; LLM-суммари при ~50k токенов (транскрипт на диск); явный `compact` | контекст конечен |
| 3. Устойчивость | s07 | граф задач (DAG) в JSON-файлах: `blockedBy`, `blocks`, автоматическая разблокировка | план живёт в памяти и стирается сжатием |
| | s08 | фоновые задачи (daemon-потоки, очередь уведомлений) | долгие команды блокируют цикл |
| 4. Команды | s09 | тиммейты с идентичностью + асинхронные почтовые ящики (JSONL) | субагенты одноразовые и не общаются |
| | s10 | протоколы request–response (согласование плана, завершение работы) | хаотичная координация |
| | s11 | автономия: в простое агент сам берёт свободные задачи с доски; повторная вставка «кто я» после сжатия | lead раздаёт всё вручную; агент «теряет себя» |
| | s12 | изоляция: каждая задача в своём `git worktree`, журнал событий | агенты правят одни файлы |

**Уроки из промышленных систем (по лекции):**
- **Субагенты** параллельно с отдельными контекстами заметно повышают качество на исследовательских задачах, но тратят **в разы больше
  токенов**; в одном опубликованном разборе ~80% разброса качества объяснялось просто объёмом использованного контекста, остальное —
  числом вызовов инструментов и выбором модели.
- **Учите оркестратор делегировать:** каждому субагенту — чёткая цель, формат ответа, подсказки по инструментам; без явных правил агенты
  порождают десятки субагентов на простые запросы, дублируют поиск. Масштабируйте усилия под сложность запроса.
- **Артефакты — в файловую систему**, а не через пересказ цепочкой агентов («испорченный телефон»).
- **Стабильный префикс промпта** — новое только дописывается в конец: тогда работает кэширование префикса, и стоимость диалога растёт
  линейно, а не квадратично.
- **Описания инструментов** — часть промпта: их стоит тестировать и улучшать (в т.ч. с помощью модели).
- **Оценка по конечному состоянию**, а не по шагам: агенты приходят к результату разными путями.
- Обновление агентов «на лету» — постепенное переключение трафика между версиями (stateful-системы нельзя просто перезапустить).

### 13. Безопасность агентов

- **Prompt injection:** содержимое страниц, писем, файлов, результатов инструментов — **данные, не команды**; модель должна не исполнять
  найденные там инструкции. Разделяйте каналы, помечайте недоверенный текст.
- **Минимальные права:** песочница путей и сети, read-only по умолчанию, подтверждение необратимых действий (удаление, платежи, отправка писем).
- **Секреты** — не в промпте и не в коде; логирование всех действий; лимиты на число шагов и стоимость.
- Протоколы подключения инструментов: function calling в API, **MCP** (Model Context Protocol) — стандарт подключения внешних
  инструментов и данных к агентам.

## Часть D. Локальный запуск

### 14. Квантование и llama.cpp

`llama-cpp-python` — обёртка над llama.cpp: быстрый инференс на CPU (и частичная выгрузка слоёв на GPU), формат **GGUF** с квантованием,
минимум зависимостей, OpenAI-совместимый сервер. Подходит для ноутбука, сервера без GPU, закрытого контура.

```python
from huggingface_hub import hf_hub_download
from llama_cpp import Llama
path = hf_hub_download("Qwen/Qwen2.5-0.5B-Instruct-GGUF", "qwen2.5-0.5b-instruct-q4_k_m.gguf", local_dir="models")  # 0.46 ГБ
llm = Llama(model_path=path, n_ctx=2048, n_threads=4, n_gpu_layers=0, verbose=False)
llm.create_chat_completion(messages=[{"role": "user", "content": "Что такое машинное обучение?"}], max_tokens=256)
# в семинаре — llm("…") без chat template: модель сначала дописала вопрос «И как это влияет на бизнес?»
```

Типы квантования GGUF: `Q8_0` (почти без потерь), `Q5_K_M`, **`Q4_K_M`** (типичный компромисс, ~4.8 бита на вес), `Q3_K`, `Q2_K` (заметная
деградация). Память ≈ параметры × биты / 8 + KV-кэш. Другие варианты: Ollama (удобная обёртка над llama.cpp), **vLLM** (сервер с
PagedAttention и непрерывным батчингом — для высокой нагрузки на GPU), TGI, SGLang.

### Чек-лист

- [ ] Сначала промпт и few-shot; RAG — для знаний; дообучение — для формата/поведения.
- [ ] Чанки по структуре + метаданные; гибридный поиск + реранкер; мерить recall@k на своих вопросах.
- [ ] В промпте: «только по контексту», «не знаешь — скажи», цитаты; низкая температура.
- [ ] Chat template модели (не склеивать роли вручную); `return_full_text=False`.
- [ ] Агент: валидировать аргументы инструментов, ограничить права и число шагов, логировать; содержимое инструментов — данные, не команды.
- [ ] Оценка по частям: поиск, faithfulness, конечный результат.
