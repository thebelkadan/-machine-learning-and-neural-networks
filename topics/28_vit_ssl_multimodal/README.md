# 28. Vision Transformer, self-supervised и мультимодальные модели

[Шпаргалка (ноутбук)](../../cheatsheet.ipynb) · [Оглавление курса](../../README.md)

**Суть.** **Vision Transformer (ViT)** режет картинку на патчи 16×16, превращает каждый в токен и обрабатывает обычным
трансформером (тема 23). У него нет встроенных предположений о локальности и сдвигах, как у свёрток, поэтому на малых данных
он проигрывает CNN, а на больших (или с сильными аугментациями и предобучением) — выигрывает. Предобучают такие модели
**без разметки**: контрастивно (SimCLR, MoCo), самодистилляцией (DINO) или восстановлением замаскированных патчей (MAE).
**CLIP** учит общее пространство для картинок и текстов на 400 млн пар «изображение — подпись» и умеет классифицировать
**без обучения** (zero-shot): класс — это текст «a photo of a …». Современные **vision-language модели** (LLaVA, Qwen-VL)
соединяют визуальный энкодер с LLM.

| Термин | Определение |
|---|---|
| Патч / patch embedding | кусок картинки $P\times P$, линейно проецируется в вектор размерности $d$ |
| [CLS]-токен | обучаемый токен, его выход — представление всей картинки |
| Индуктивное смещение | заложенные в архитектуру предположения (локальность и эквивариантность к сдвигам у CNN) |
| Self-supervised learning | обучение на задаче, разметка для которой берётся из самих данных |
| MAE | маскируем 75% патчей, восстанавливаем пиксели; энкодер видит только видимые патчи |
| DINO | ученик предсказывает выход учителя (EMA ученика) на других кропах той же картинки |
| Linear probe | заморозить энкодер и обучить только линейный классификатор на его признаках |
| CLIP | два энкодера (картинка, текст), обучение InfoNCE на парах; zero-shot по текстовым описаниям классов |
| VLM | визуальный энкодер + проектор + LLM; понимает картинку и отвечает текстом |

**Ключевые формулы**

$$
N=\frac{HW}{P^2},\qquad z_0=[x_{\mathrm{cls}};\,x_1E;\dots;x_NE]+E_{\mathrm{pos}},\qquad
\mathcal L_{\mathrm{CLIP}}=\frac12\Big(\mathrm{CE}\big(\tfrac{IT^\top}{\tau},\,\mathrm{diag}\big)+\mathrm{CE}\big(\tfrac{TI^\top}{\tau},\,\mathrm{diag}\big)\Big)
$$

**Часть A. Vision Transformer**

<details>
<summary><b>1. Картинка как последовательность патчей</b></summary>

Трансформер работает с последовательностью векторов. Подать каждый пиксель токеном нельзя: для картинки 224×224 это 50 176
токенов, а внимание стоит $O(N^2)$. ViT (Dosovitskiy et al., 2020, «An Image is Worth 16x16 Words») режет изображение на
непересекающиеся патчи $16\times16$ — получается $14\times14=196$ токенов, как у короткого текста.

Конвейер:
1. Разрезать картинку $H\times W\times C$ на $N=HW/P^2$ патчей, развернуть каждый в вектор длины $P^2C$.
2. Линейная проекция $E$ в размерность модели $d$ (на практике — свёртка `Conv2d(C, d, kernel_size=P, stride=P)`, это то же самое).
3. Добавить в начало обучаемый токен **[CLS]**, прибавить обучаемые **позиционные эмбеддинги** $E_{\mathrm{pos}}$.
4. Стопка блоков энкодера трансформера (pre-LN, MHSA + MLP, тема 23).
5. Голова-классификатор на выходе [CLS] (или на среднем по токенам).

Размеры: ViT-B/16 — 12 слоёв, $d=768$, 12 голов, 86 млн параметров; ViT-L/16 — 24 слоя, $d=1024$, 307 млн; ViT-H/14 — 632 млн.
Запись «/16» — размер патча: меньше патч — больше токенов — точнее и дороже.

```python
class PatchEmbed(nn.Module):
    def __init__(self, img=224, patch=16, in_ch=3, d=768):
        super().__init__()
        self.proj = nn.Conv2d(in_ch, d, kernel_size=patch, stride=patch)   # линейная проекция патчей
        self.cls = nn.Parameter(torch.zeros(1, 1, d))
        self.pos = nn.Parameter(torch.zeros(1, (img // patch) ** 2 + 1, d))
    def forward(self, x):                                                  # x: [B, 3, 224, 224]
        x = self.proj(x).flatten(2).transpose(1, 2)                         # [B, 196, 768]
        return torch.cat([self.cls.expand(len(x), -1, -1), x], 1) + self.pos
```

</details>

<details>
<summary><b>2. Индуктивные смещения: почему ViT нужно много данных</b></summary>

Свёртка «знает» заранее: соседние пиксели связаны (локальность), а объект остаётся объектом при сдвиге (эквивариантность,
тема 16). У ViT этого почти нет: локальность есть только внутри патча, связи между патчами и даже их взаимное расположение
он учит из данных. Поэтому:

- На ImageNet-1k (1.3 млн картинок) с нуля ViT-B хуже ResNet того же размера.
- После предобучения на JFT-300M (300 млн) или ImageNet-21k ViT обгоняет CNN и масштабируется лучше.
- **DeiT** (Touvron et al., 2021) обучил ViT на одном ImageNet-1k за счёт сильных аугментаций (RandAugment, Mixup, CutMix,
  random erasing), регуляризации и дистилляции от CNN-учителя через отдельный distillation-токен.

Пример кода этой темы: на цифрах, разбросанных по холсту 16×16, CNN с 19 тыс. параметров даёт 0.89 точности на 200 примерах, а
ViT со 103 тыс. — 0.23. С аугментацией (каждую эпоху новое положение цифры) ViT поднимается до 0.93 — данные заменяют
встроенное знание о сдвигах.

Что выучивают позиционные эмбеддинги: соседние патчи получают похожие векторы, проступает двумерная структура строк
и столбцов — модель сама восстанавливает геометрию. При дообучении на другом разрешении их интерполируют (см. раздел
«2. Позиционные эмбеддинги при смене разрешения»).

</details>

<details>
<summary><b>3. Иерархические ViT и «модернизированные» CNN</b></summary>

Классический ViT — «плоский»: все слои работают на одной сетке 14×14. Для детекции и сегментации (темы 17–18) нужны карты
признаков разного масштаба и линейная по числу пикселей сложность.

- **Swin Transformer** (Liu et al., 2021): внимание внутри локальных окон 7×7 со сдвигом окон через слой (shifted windows),
  слияние патчей между стадиями — пирамида признаков, как у ResNet; сложность линейна по размеру картинки.
- **ConvNeXt** (Liu et al., 2022): ResNet, постепенно переделанный по рецептам трансформеров (большие ядра 7×7, depthwise-свёртки,
  LayerNorm, GELU, inverted bottleneck, обучение по рецепту DeiT), догнал Swin. Вывод: значительная часть успеха ViT — в
  рецепте обучения, а не только во внимании.
- Гибриды: свёрточный «стебель» вместо нарезки на патчи, внимание на верхних слоях (CoAtNet, MaxViT).

На практике в 2020-х: для классификации и признаков — ViT/ConvNeXt, предобученные без учителя или на парах «картинка — текст»;
для плотных задач — Swin/ConvNeXt-бэкбоны или ViT с адаптерами.

</details>

**Часть B. Self-supervised обучение зрения**

<details>
<summary><b>4. Зачем обучение без разметки и как оно развивалось</b></summary>

Разметка дорогая, а неразмеченных картинок — миллиарды. Идея: придумать задачу, ответ на которую известен из самих данных, и
надеяться, что для её решения сеть выучит полезные признаки. Качество проверяют **linear probe** (линейный классификатор на
замороженных признаках), k-NN по признакам или дообучением (fine-tuning) на целевой задаче.

| Поколение | Задача | Примеры |
|---|---|---|
| Pretext-задачи | угадать поворот, собрать пазл из кусков, раскрасить чёрно-белое | RotNet, Jigsaw |
| Контрастивные | два аугментированных вида одной картинки — близко, другие картинки — далеко | SimCLR, MoCo (тема 19) |
| Без негативов | предсказать представление учителя; коллапс предотвращается асимметрией | BYOL, SimSiam, DINO |
| Маскированное моделирование | восстановить закрытые патчи | BEiT, MAE, iBOT |
| Совмещённые | DINO + маскирование + большой курированный датасет | DINOv2 |

Аугментации задают, какие различия считать несущественными (тема 19): обрезка, отражение, цвет, размытие. Для медицинских или
спутниковых снимков набор нужно подбирать заново.

</details>

<details>
<summary><b>5. Masked Autoencoders (MAE)</b></summary>

MAE (He et al., 2021) переносит идею BERT (тема 23) на картинки:
1. Случайно закрыть **75%** патчей.
2. **Энкодер** (большой ViT) обрабатывает только видимые 25% — обучение в 3–4 раза дешевле.
3. Лёгкий **декодер** получает видимые токены + обучаемые mask-токены на местах закрытых и восстанавливает пиксели.
4. Лосс — MSE только по закрытым патчам (по нормированным пикселям патча).
5. После обучения декодер выбрасывают; энкодер дообучают на задаче.

Почему маска такая большая: в картинке огромная избыточность — соседний патч почти полностью восстанавливается интерполяцией.
При 75% задача становится семантической: нужно понимать, что изображено. Признаки MAE слабее в linear probe, чем у
контрастивных методов, но хорошо дообучаются (fine-tuning).

</details>

<details>
<summary><b>6. DINO и DINOv2: самодистилляция</b></summary>

**DINO** (Caron et al., 2021): две копии сети — **ученик** и **учитель**; учитель — экспоненциальное скользящее среднее весов
ученика (EMA), градиентов не получает.
- Из картинки делают 2 больших «глобальных» кропа и несколько маленьких «локальных».
- Учитель видит только глобальные кропы, ученик — все.
- Выходы — распределения по $K$ (например, 65 536) «прототипам»; ученик минимизирует кросс-энтропию до распределения учителя
  на другом кропе: «по кусочку угадай, что учитель видит на целой картинке».
- От коллапса (все картинки в один выход) защищают **центрирование** (из логитов учителя вычитается скользящее среднее) и
  **заострение** (низкая температура учителя).

Неожиданное свойство: карты внимания [CLS] у DINO-ViT без всякой разметки выделяют объекты — почти готовая сегментация.
**DINOv2** (Oquab et al., 2023): DINO + маскированное моделирование (iBOT) + 142 млн курированных картинок → универсальные
признаки, которые хорошо работают замороженными для классификации, сегментации, оценки глубины, поиска похожих.

</details>

**Часть C. Мультимодальные модели**

<details>
<summary><b>7. CLIP: картинки и тексты в одном пространстве</b></summary>

**CLIP** (Radford et al., 2021): 400 млн пар «картинка — подпись» из интернета; энкодер картинок (ViT или ResNet) и энкодер
текстов (трансформер); оба выхода проецируются в общее пространство и нормируются.

**Обучение:** в батче $B$ пар матрица косинусных сходств $B\times B$; на диагонали — настоящие пары. Симметричный InfoNCE (тема 19):
для каждой картинки найти её подпись среди $B$ текстов и наоборот. Батч — 32 768, температура $\tau$ обучается.

**Zero-shot классификация:**
1. Для каждого класса составить текст: «a photo of a {класс}».
2. Получить эмбеддинги текстов один раз.
3. Для картинки — косинус с каждым текстом, softmax с температурой → вероятности классов.

Без единого размеченного примера CLIP ViT-L/14 даёт на ImageNet ~76% top-1 — уровень ResNet-50, обученного с учителем.
Шаблоны промптов важны: «a photo of a {}», «a blurry photo of a {}» и усреднение эмбеддингов нескольких шаблонов
(prompt ensembling) добавляют несколько процентов.

Пример кода этой темы: косинусные сходства CLIP между картинками и подписями лежат в узком диапазоне (~0.2–0.3), но после умножения
на обученную обратную температуру $1/\tau=100$ и softmax ответ становится уверенным.

Ограничения: слабо считает объекты и понимает пространственные отношения («слева от»), чувствителен к формулировке,
наследует перекосы интернет-данных, плохо работает на узких доменах (медицина) без дообучения.

</details>

<details>
<summary><b>8. Где применяют CLIP-подобные модели</b></summary>

- **Поиск** картинок по тексту и наоборот (векторный поиск, тема 19).
- **Разметка и фильтрация** данных: отобрать картинки, подходящие под описание; оценить соответствие подписи (CLIP-score, тема 27).
- **Open-vocabulary детекция и сегментация**: OWL-ViT, Grounding DINO, SAM + CLIP — найти объекты, заданные текстом.
- **Генерация**: текстовый энкодер CLIP — условие для диффузионных моделей (Stable Diffusion, тема 27).
- **Признаки** для своих задач: linear probe на эмбеддингах CLIP часто сильнее ImageNet-признаков.
- Улучшения обучения: **SigLIP** (сигмоидальный лосс по парам вместо softmax по батчу — проще масштабировать), EVA-CLIP,
  OpenCLIP (открытое воспроизведение на LAION).

</details>

<details>
<summary><b>9. Vision-language модели (VLM)</b></summary>

Задача — отвечать текстом на вопросы о картинке, описывать, читать документы. Общая схема:

1. **Визуальный энкодер** (обычно замороженный CLIP/SigLIP ViT) → последовательность токенов-патчей.
2. **Проектор** (линейный слой или MLP; в BLIP-2 — Q-Former с обучаемыми запросами) переводит их в пространство эмбеддингов LLM.
3. **LLM** (тема 24) получает визуальные токены вперемешку с текстовыми и генерирует ответ.

Обучение (LLaVA): этап 1 — учим только проектор на парах «картинка — подпись» (выравнивание); этап 2 — instruction tuning
(тема 25) на диалогах о картинках, размораживая LLM. Другие линии: Flamingo (cross-attention слои в замороженной LLM),
Qwen-VL, InternVL, нативно мультимодальные модели, обучаемые на смеси с самого начала.

Типичные слабости: галлюцинации объектов, которых нет на картинке; мелкий текст (решается высоким разрешением и
нарезкой на тайлы); подсчёт объектов.

</details>

<summary><b>10. Практика</b></summary>

- Предобученные модели: `timm` (сотни CNN и ViT), Hugging Face `transformers` (`ViTModel`, `CLIPModel`, `AutoModel` для DINOv2),
  `open_clip`.
- Мало данных → замороженный бэкбон (DINOv2, CLIP) + linear probe или k-NN; больше данных → дообучение с меньшим lr для бэкбона.
- Препроцессинг — ровно тот, с которым модель обучалась (размер, нормировка); у CLIP своя нормировка.

- Zero-shot как бейзлайн: прежде чем размечать данные, проверьте, что даёт CLIP с хорошими промптами.

**Чек-лист**
- Мало размеченных данных: SSL-бэкбон + linear probe; сравнить с CNN, предобученной на ImageNet.
- ViT с нуля — только с сильными аугментациями (Mixup, CutMix, RandAugment) и регуляризацией.
- Для плотных задач — иерархические бэкбоны (Swin, ConvNeXt).
- Для задач «картинка + текст» — CLIP/SigLIP-эмбеддинги; для вопросов-ответов — VLM.

**Математика и выводы**

<details>
<summary><b>1. Число токенов и стоимость</b></summary>

Для картинки $H\times W$ и патча $P$: $N=HW/P^2$ токенов. Слой стоит $\approx 12Nd^2$ (проекции и MLP) $+\,2N^2d$ (внимание) FLOPs
на прямой проход (тема 23). Для $224^2$, $P=16$: $N=196$, и при $d=768$ доля внимания мала ($2N^2d\ll12Nd^2$, так как $N\ll6d$).
При $P=8$ токенов в 4 раза больше, внимание дороже в 16 раз. Переход на $448^2$ при $P=16$ даёт $N=784$ — внимание уже
сравнимо с остальным. Swin ограничивает внимание окном $M\times M$: стоимость $\approx 2NM^2d$ — линейна по $N$.

</details>

<details>
<summary><b>2. Позиционные эмбеддинги при смене разрешения</b></summary>

Обученные $E_{\mathrm{pos}}\in\mathbb R^{(N+1)\times d}$ привязаны к сетке $\sqrt N\times\sqrt N$. При дообучении на большем разрешении
сетка становится $\sqrt{N'}\times\sqrt{N'}$: эмбеддинги патчей переставляют в двумерную решётку $\sqrt N\times\sqrt N\times d$,
**бикубически интерполируют** до $\sqrt{N'}\times\sqrt{N'}$, а эмбеддинг [CLS] оставляют как есть. Это работает потому, что
выученные эмбеддинги гладко зависят от координат (соседние патчи — похожие векторы). Относительные позиции (RoPE-2D,
относительный bias в Swin) переносятся на другие размеры естественнее.

</details>

<details>
<summary><b>3. Лосс CLIP</b></summary>

Нормированные эмбеддинги картинок $I\in\mathbb R^{B\times d}$ и текстов $T\in\mathbb R^{B\times d}$, логиты $S=IT^\top/\tau$:

$$
\mathcal L=\frac1{2B}\sum_{i=1}^{B}\Big(-\log\frac{e^{S_{ii}}}{\sum_je^{S_{ij}}}-\log\frac{e^{S_{ii}}}{\sum_je^{S_{ji}}}\Big).
$$

Первое слагаемое — классификация «какая подпись моя» для каждой картинки, второе — «какая картинка моя» для каждого текста.
Это InfoNCE с $B-1$ негативами (тема 19); оценка взаимной информации растёт с $\log B$ — поэтому огромные батчи.
$\tau$ параметризуют как $e^{t}$ и обучают (у CLIP $1/\tau$ доходит до ограничения 100). **SigLIP** заменяет softmax на независимую
логистическую регрессию для каждой пары: $\mathcal L=-\frac1B\sum_{i,j}\log\sigma\big(z_{ij}(t\cos_{ij}+b)\big)$, $z_{ij}=+1$ для своей пары и $-1$ для чужой — не нужна
нормировка по всему батчу, проще распределённое обучение.

**Zero-shot как линейный классификатор:** эмбеддинги текстов классов $t_1,\dots,t_K$ — это строки матрицы весов линейной головы;
$p(k\mid x)=\operatorname{softmax}_k(\langle f(x),t_k\rangle/\tau)$. Значит, промпты — способ задать веса классификатора словами.

</details>

<details>
<summary><b>4. Почему MAE не коллапсирует, а DINO нужно центрирование</b></summary>

**MAE** предсказывает **пиксели** — цель фиксирована и не зависит от сети, тривиального решения нет.

**DINO** предсказывает выход другой сети (учителя), и у задачи есть тривиальные решения:
- все входы → одно и то же распределение (схлопывание в одну моду);
- все входы → равномерное распределение.

Ученик $p_s=\operatorname{softmax}(g_s(x')/\tau_s)$, учитель $p_t=\operatorname{softmax}\big((g_t(x)-c)/\tau_t\big)$, лосс $H(p_t,p_s)$.
**Центрирование** $c\leftarrow mc+(1-m)\,\mathbb E_{\text{батч}}[g_t(x)]$ не даёт одному измерению доминировать (но толкает к
равномерности), **заострение** (малая $\tau_t\approx0.04$) толкает к уверенным, неравномерным распределениям. Вместе они
балансируют. Учитель — EMA ученика $\theta_t\leftarrow\lambda\theta_t+(1-\lambda)\theta_s$, $\lambda\to1$ — медленно меняющаяся «цель», что тоже
стабилизирует обучение (как target network в DQN, тема 31).

</details>

<summary><b>Вопросы с собеседований</b></summary>

Сначала ответьте сами, потом раскройте ответ.

<details>
<summary>Почему ViT на малых данных хуже CNN?</summary>

нет индуктивных смещений локальности и инвариантности к сдвигам; их приходится выучивать из данных (в примере 0.23 против 0.89 на 200 картинках).

</details>

<details>
<summary>Чем патч-эмбеддинг отличается от свёртки?</summary>

ничем: это `Conv2d` с ядром и шагом $P$; дальше сходство заканчивается — патчи взаимодействуют через глобальное внимание.

</details>

<details>
<summary>Зачем [CLS]-токен?</summary>

собирает информацию со всех патчей для классификации; альтернатива — среднее по токенам (часто не хуже).

</details>

<details>
<summary>Почему MAE маскирует 75%, а BERT — 15%?</summary>

картинки избыточны: соседний патч восстанавливается интерполяцией, задача должна стать трудной.

</details>

<details>
<summary>Как CLIP классифицирует без обучения?</summary>

сравнивает эмбеддинг картинки с эмбеддингами текстов «a photo of a {класс}»; тексты — это веса линейного классификатора.

</details>

<details>
<summary>Что такое linear probe и зачем?</summary>

обучить только линейный слой на замороженных признаках; меряет качество представлений без влияния дообучения.

</details>

<details>
<summary>Почему VLM галлюцинируют объекты?</summary>

языковая модель достраивает правдоподобное по контексту, а визуальный сигнал проходит через узкий проектор; помогают высокое разрешение и данные с «отрицательными» вопросами.

</details>

```python
# Мини-ViT с нуля против маленькой CNN: цифры 8×8 в случайном месте холста 16×16
import warnings; warnings.filterwarnings("ignore")
import numpy as np, torch, torch.nn as nn, torch.nn.functional as F
from sklearn.datasets import load_digits
d = load_digits(); IM = d.images.astype(np.float32) / 16; Y = torch.tensor(d.target)
rng = np.random.default_rng(0)
def place(idx, rng):                                            # цифра в случайной позиции
    out = np.zeros((len(idx), 1, 16, 16), np.float32)
    for k, i in enumerate(idx):
        dy, dx = rng.integers(0, 9, 2); out[k, 0, dy:dy + 8, dx:dx + 8] = IM[i]
    return torch.tensor(out)
X = place(range(len(IM)), rng)
perm = torch.randperm(len(X), generator=torch.Generator().manual_seed(0)); tr, te = perm[:1200], perm[1200:]

class ViT(nn.Module):
    def __init__(self, p=4, d=64, depth=2, heads=4, n_cls=10):
        super().__init__(); self.p = p
        self.patch = nn.Linear(p * p, d)                           # патч 4×4 → токен
        self.cls = nn.Parameter(torch.zeros(1, 1, d)); self.pos = nn.Parameter(torch.randn(1, (16 // p) ** 2 + 1, d) * 0.02)
        layer = nn.TransformerEncoderLayer(d, heads, 4 * d, dropout=0.0, batch_first=True, norm_first=True)
        self.enc = nn.TransformerEncoder(layer, depth, enable_nested_tensor=False); self.ln = nn.LayerNorm(d); self.head = nn.Linear(d, n_cls)
    def forward(self, x):
        B, p = len(x), self.p
        patches = x.unfold(2, p, p).unfold(3, p, p).reshape(B, -1, p * p)      # [B, 16 патчей, 16 пикселей]
        z = torch.cat([self.cls.expand(B, -1, -1), self.patch(patches)], 1) + self.pos
        return self.head(self.ln(self.enc(z)[:, 0]))               # классификация по [CLS]

def make_cnn():
    return nn.Sequential(nn.Conv2d(1, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(),
                         nn.AdaptiveMaxPool2d(1), nn.Flatten(), nn.Linear(64, 10))
def train(model, idx, epochs=40, augment=False):
    torch.manual_seed(0); opt = torch.optim.AdamW(model.parameters(), 2e-3, weight_decay=0.05); arng = np.random.default_rng(1)
    for ep in range(epochs):
        for b in idx[torch.randperm(len(idx))].split(64):
            xb = place(b.tolist(), arng) if augment else X[b]      # аугментация: новое положение цифры
            loss = F.cross_entropy(model(xb), Y[b]); opt.zero_grad(); loss.backward(); opt.step()
    with torch.no_grad(): return (model(X[te]).argmax(1) == Y[te]).float().mean().item()

n_params = lambda m: sum(p.numel() for p in m.parameters())
torch.manual_seed(0); print(f"параметров: ViT {n_params(ViT()):,}, CNN {n_params(make_cnn()):,}")
for n in (200, 1200):
    torch.manual_seed(0); v = ViT(); torch.manual_seed(0); c = make_cnn()
    print(f"обучение на {n:4d}: ViT {train(v, tr[:n]):.3f} | CNN {train(c, tr[:n]):.3f}")
torch.manual_seed(0); print(f"ViT на 1200 + аугментация сдвигами (80 эпох): {train(ViT(), tr, epochs=80, augment=True):.3f}")
```

```text
обучение на  200: ViT 0.233 | CNN 0.894
обучение на 1200: ViT 0.658 | CNN 0.980
ViT на 1200 + аугментация сдвигами (80 эпох): 0.930
```

```python
# CLIP: zero-shot классификация и сходства «картинка — текст» (модель ~600 МБ при первом запуске)
from sklearn.datasets import load_sample_images
try:
    from transformers import CLIPModel, CLIPProcessor
    name = "openai/clip-vit-base-patch32"
    clip, proc = CLIPModel.from_pretrained(name).eval(), CLIPProcessor.from_pretrained(name)
    china, flower = load_sample_images().images                     # две картинки из sklearn: храм и цветок
    images = [china, flower, china[:, ::-1], flower[100:400, 200:550]]
    texts = ["a photo of a temple", "a photo of a flower", "a photo of a cat", "a photo of a car", "a photo of a beach"]
    with torch.no_grad():
        inp = proc(text=texts, images=images, return_tensors="pt", padding=True)
        img = F.normalize(clip.get_image_features(pixel_values=inp["pixel_values"]), dim=-1)
        txt = F.normalize(clip.get_text_features(input_ids=inp["input_ids"], attention_mask=inp["attention_mask"]), dim=-1)
        cos = img @ txt.T                                           # косинусы лежат в узком диапазоне
        probs = (clip.logit_scale.exp() * cos).softmax(-1)          # 1/τ = 100 делает softmax уверенным
    names = ["храм", "цветок", "храм (отражение)", "цветок (кроп)"]
    print("классы:", [t.split(" of a ")[1] for t in texts])
    for n_, c_, p_ in zip(names, cos, probs):
        print(f"{n_:17s} косинусы {np.round(c_.numpy(), 3)} → вероятности {np.round(p_.numpy(), 2)}")
except Exception as e:
    print("не удалось загрузить с Hugging Face Hub (нужен интернет):", type(e).__name__, str(e)[:120])
```
